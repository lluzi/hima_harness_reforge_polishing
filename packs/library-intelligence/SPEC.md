# E1 qualification contract

`qualificationManifest` is a Site-owned JSON file with schema `hima-library-qualification-input/1`. It names the exact wrapper, Python path/version/hash, API root/build label, hashes of `tmlib.py`, `_tmlib.so`, and `lib/libparser_wrapper.so`, the worker hash, a staged Permit snapshot path/hash, and exactly one source of each role `vendor-fixture`, `saed14`, `tsmc28` with an expected SHA-256. These API filenames are fixed by the worker. Paths are absolute plain files; inputs and runtime must be under the Permit read roots. A bounded manual invocation may write `flow/qualification/receipt.json` with schema `hima-library-qualification/1`; the default Pack graph does not invoke it.

The manual worker sequence is Permit and path check, runtime identity, source hash, native read and query, workspace copy, re-read and invariant comparison, source hash after. The native API runs in a child process for each source. Exit 139, a signal, a missing child result, an identity mismatch, or a copy mismatch blocks the receipt. No source facts are emitted on a blocked input. The parent writes one result per declared input; later inputs are explicitly `not-run` after a blocker. The Reader verifies the receipt, source hashes, and the hashed `child.json` query evidence before emitting a zero qualification indicator. To read a manually produced receipt, the same worker bytes must be staged at `flow/tools/libapi_worker.py`; default workspace preparation does not stage them.

The `permitSha256` field identifies the staged Permit bytes the worker read. Host integration must independently match this SHA to its loaded Site Permit before exposing a runnable tool. A Site binding alone cannot prove that identity, so this development Pack writes `nativeStatus: passed` but overall `status: blocked` and Reader indicator zero even after three native passes. `apiBuild` is a Site label, supported by the three API hashes; it is not a vendor-authenticated build proof. The Host still needs to pin the `edarun` executable identity. The qualified runtime and representative samples do not qualify a full Library corpus.

The 2026-09-24 native probe ran only with `empyrean-license status` selected=new (QuaLib 2026, port 59099), with no XTop client. This Pack must not overlap XTop old/59001. The current Site/Job capacity contract cannot mechanically attest selected license state or enforce this cross-tool exclusion; product admission remains blocked until that integration gate is implemented and tested.
