# E1 qualification contract

`qualificationManifest` is a Site-owned JSON file with schema `hima-library-qualification-input/1`. It names `/usr/local/bin/edarun` with its resolved path and SHA-256, the Python path/version/hash, API root/build label, hashes of `tmlib.py`, `_tmlib.so`, and `lib/libparser_wrapper.so`, the worker hash, the loaded Permit path/hash, the exact QuaLib 2026 new/59099 selection, and exactly one source of each role `vendor-fixture`, `saed14`, `tsmc28` with an expected SHA-256. These API filenames are fixed by the worker. Paths are absolute plain files; inputs and runtime must be under the Host-loaded Permit read roots.

At prelaunch, the Host writes `<workspace>/hima-library-host-attestation.json`, binding the admitted run, node, attempt and Job session. The worker requires that exact path and carries the identity into its receipt before the sequence Permit/path check, runtime identity, source hash, native read/query, workspace copy, re-read/invariant comparison, and source hash after. The Reader rejects relocation, replay against another launch identity, or a receipt/attestation mismatch. Python validation alone does not establish Host authority: before `library_qualification_ok=1` enters an observation, Fabric must match the receipt to a launched and successfully finished `qualify-api` Job record in the same Run. The native API runs in a child process for each source. Exit 139, a signal, a missing child result, an identity mismatch, or a copy mismatch blocks the receipt. No source facts are emitted on a blocked input. The parent writes one result per declared input; later inputs are explicitly `not-run` after a blocker. A higher same-Run/node attempt may replace an attestation only while no qualification output exists; retained output blocks in-place retry and requires a new Campaign workspace.

The `permitSha256` field must equal the exact Permit bytes retained by `loadSite`; a manifest claim cannot replace that identity. `apiBuild` is a Site label supported by the three API hashes; it is not a vendor-authenticated build proof. The qualified runtime and representative samples do not qualify a full Library corpus.

The tool claims `QuaLib-2026-new-59099: 1`, and the Host admits it only on a one-Job Site. For Hima-managed Jobs, the same existing Site cap prevents a current XTop Job from preceding this launch and prevents XTop from starting while this Job remains open. External processes are outside this accounting and remain an L4 operator precheck. This attests the Site owner's selected mode declaration; the retained 2026-09-24 real-tool run remains the only native evidence until the runnable Host path is requalified on the Site.
