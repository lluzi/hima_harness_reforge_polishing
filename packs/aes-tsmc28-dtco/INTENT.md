## Golden Flow

The Site binds `flowRoot` to a separately staged copy of `./flow` plus its private `inputs.json`.
Run `/usr/bin/python3 flow/stages.py STAGE WORKSPACE [ROUTE]` for the domain stages; probe invocation
remains `/usr/bin/python3 flow/probe.py --workspace WORKSPACE --period PERIOD_NS`.
The declared workspace copies are in contract.yml. All results are in that Campaign's own workspace.
No tool modifies the staged inputs, reference libraries, old runs or either readonly source checkout.

## Answers

The Run fixes `target_period_ns` (ns, 0.1..5, default 0.5). Strategies are `periodNs` (same units and
bounds, default 0.35) and `algorithmRevision` (integer 0..99, default 0). The initial probe loop has
two generations. The full-method outer loop defaults to one generation in this pilot version; the Run may explicitly
set another supported generation budget at start. Its fixed time/retry budget still applies. Max two generated cells are
admitted by Site inputs. Six fork branches share, rather than multiply, the Site's Job cap.

Each route's Workshop writes source-hashed selected ids; its code identity is recorded at launch.
A deterministic, Boolean/profile-aware round-robin merge provides the finite build allocation.
Readers derive facts from held artifacts. Library rejection, missing prerequisites, zero adoption,
verification errors, unavailable metrics and negative findings remain different outcomes.

## Ambiguities resolved

The probe's timing success is only a mining input. Two fresh synthesis arms use one shared template,
followed by matched post-route measurement; the probe is not their comparison baseline.
Predicted Liberty and abstract geometry are explicitly exploratory, not characterized/signoff IP.
The final Judge uses current complete evidence, never an earlier nested loop's success. No credible
physical metric means unknown or blocked. Negative results still belong in the report and archive.
PLS-25 validates the method and bounded tool bring-up; full scientific pilot acceptance is PLS-18.
