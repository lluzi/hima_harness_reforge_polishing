| 分支 | 当前结论 | 后续决策 |
| --- | --- | --- |
| 服务基础 | 同一 Library 分析基础服务 Library-only 和 Library+Design 两类关注范围 | 库分析对象、PDK 相关信息的边界与典型决策 |

## 第一轮已确认

### Q1 服务谁及核心价值

- 不按芯片设计者、DTCO 工程师等职业划分产品重心。两类人分别是只关心 Library、同时关心 Library
  和 Design；两者依靠同一基础。
- 两类入口是 Library 与 Design。前者包括 Library 及相关 PDK 的库信息；后者包括具体设计的 DEF、
  Liberty、Netlist、Timing Report 等。文件格式本身不能决定归属。
- Library 本身的数据洞察不可或缺，要研究库值得做什么、需要做什么，以及哪些东西可转化为设计收益。
- 有 Design 后结合两侧信息，对设计形成具体指导。

### Q2 原型价值与交互改进

要保留：

1. Overall 风险地图，以矩阵/表格显示整套库中风险的位置与类型。
2. 看到问题即可直觉式点击，获得新信息。
3. input transition × output load Heatmap，配合标线区分可靠/不可靠区域。
4. 每个 cell 的 Sensitivity 呈现。
5. Overall rule configuration，允许用户表达规则或偏好。

要改善：

1. 每类分析尽量在一个标签页内完成，细节原地展开；减少下钻与回退。
2. 表达实际影响，使用户能感知某个 rule 的问题到底有多严重。
3. 数据与结论并排对照。
4. 用浅层逻辑与直接交互缩短信息 → 洞察 → 行动的距离，做到一目了然。
