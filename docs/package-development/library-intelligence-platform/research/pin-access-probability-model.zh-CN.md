# 基于 LEF 几何的 pin access 概率模型

日期：2026-09-29。状态：用户指定方向下的模型设计，尚未实现或对目标库校准。本文承接[方法调研](pin-accessibility-report.zh-CN.md)，将目标进一步明确为：从物理几何与合法布线约束出发，计算每个 pin 和 standard cell 在声明环境中的接入成功概率，并保留未来可校准的参数与证据。

**可以在没有真实 P&R 标签时开始计算概率。** 对给定 cell、规则和环境，是否存在合法接入方案是一个确定性的可行性问题；对放置位置、邻居、网络需求和资源占用等环境变化积分，就得到模型概率。真实工具结果以后用来检验几何/规则模型、修正环境分布，并刻画求解算法的成功率。

没有实测分布时，数值是评价协议下的场景概率，而非部署频率的估计；必须先给出有限权重表或明确采样器，输出参考 profile、压力曲线与敏感性范围。LEF 与规则本身只能决定给定场景的可行性。

因此第一版不需要先训练一个黑箱分类器，但要同时交付概率的事件定义、场景分布、规则覆盖与不确定性。这里的概率具有明确数学含义；其对真实设计的预测有效性仍需后续验证。

## 第一性原理与模型假设的分界

本问题可以从四条约束出发：

1. 连接必须形成从目标 pin 到指定外部接口的连续导体路径。
2. 不同网络之间不得短接，并满足已声明的金属、via、cut、enclosure、spacing 等规则。
3. 多个连接共享有限的轨道、via 位置与邻近间距资源；同一资源不能被互斥用途同时占用。
4. 一个局部可行解需要为所有指定连接义务提供相容的路径，且满足声明的层、线长、via 或其他路径预算。

这四条确定“什么算一个解”。环境出现频率、router 的路径偏好与搜索效率不由 LEF 唯一决定，需要明确的参考分布或可调假设。第一性原理约束解空间，概率模型描述这个解空间在不同环境下出现的频率；两者不能混为一个经验加权分数。

## 概率的对象和分母

用 `c` 表示具体物理 master，包括 pin/OBS 几何与视图版本；`θ` 表示固定的技术规则、via 语义和接入候选定义。环境为：

`z = (o, φ, N, g, H, M, D, T)`

| 变量 | 含义 | 早期来源 |
| --- | --- | --- |
| `o` | 合法朝向与 row/site 条件 | LEF site/symmetry 和声明的 row 规则 |
| `φ` | cell 相对各层 routing tracks 的相位 | 声明的网格；有 DEF 时读取真实 TRACKS |
| `N` | 左右及必要上下邻域的 cell、朝向、几何 | 输入库中的合法邻接组合 |
| `g` | 间距、padding、空白与相对位置 | 显式场景档位；未来由 placement 提取 |
| `H` | PDN、固定金属与 blockages | 已有物理信息或声明的合成模板 |
| `M` | 活跃端口、网络归属、同网合并关系 | 无网表时声明假设，有网表时读取真实连接 |
| `D` | 各网络需要到达的局部出口、方向、层与预算 | 分方向情景或来自粗粒度 routing demand |
| `T` | 背景网络的路径及资源占用 | 保持空间相关性的路径生成模型 |

先定义 `q_attempt(z | c, profile)` 为包含待尝试放置位置的归一化联合环境分布，`L(c,z)` 为结构性 placement 合法事件；再定义 `q_legal(z)=q_attempt(z | L=1)`。后文主指标使用 `q=q_legal`，不混用两个分母。若 `P(L)=0`，条件接入概率报“不适用”，同时 `P_usable=0`。它可以是明确有限场景的概率质量，也可以来自可重复采样器；通常不能分解为上述变量的独立乘积。`θ` 的未知规则和 `q` 的未知权重属于认知不确定性，不应假装成已经测得的随机噪声。

为避免“把很难放的 cell 只放在容易的地方，因此看起来很好”的偏差，必要时同时报告：

- `P_place`：在共同参考尝试分布下，满足结构性 placement 合法性的概率；
- `P_access | legal_place`：在合法放置条件下接入成功的概率；
- `P_usable = E_q_attempt[1(L) F] = P_place × P_cell_access`：两者同时成立的概率，其中 `P_cell_access=E_q_legal[F]`。

结构性合法性与“router 觉得容易接入”分开定义。实际 pin-aware placer 可能主动避开困难环境；应另设 `q_policy`，并与用于比较库的 `q_reference` 分开。对不同宽度 cell 的比较要声明位置/空白模板如何匹配，不把模板产生的面积偏差隐藏在概率里。

### 主指标的定义

令 `F_c(z; θ)=1` 表示：在该环境下，存在一组同时满足约束的路径，使 cell 所有活跃连接义务到达指定局部出口；否则为 0。主指标为：

`P_cell_access(c | θ, q) = E_(z~q)[F_c(z; θ)]`

`P_cell_problem(c | θ, q) = 1 − P_cell_access(c | θ, q)`

这给出了每个 standard cell 在合法放置条件下的**条件接入失败概率**，不包含结构性不可放置风险。它不是脱离规则、负载和邻居的固有常数，也不是整个芯片 routing/signoff 的失败概率。界面中必须能查看 `q`、`θ` 和局部出口定义。

## 从 LEF 构造确定性的物理模型

### 解析端口与障碍的真实语义

读取 pin 的全部相关形状、层、PORT、OBS、尺寸、单位、origin、site 与 symmetry；实例变换后再与 routing grid 对齐。不要把 pin center 当作唯一入口，也不要把每个矩形当作一个独立连接义务。

不同 PORT、MUSTJOIN、PG 和同网连接需遵守输入格式与工具语义。尤其不能直接将所有 OBS 从 PIN 中做集合相减：Cadence 的 LEF/DEF 5.7 说明，重叠的 port geometry 可覆盖 obstruction 的阻挡语义，但其他层的障碍与 via enclosure 仍可能禁止接入。[原参考手册，第 190–191 页](https://www.ispd.cc/contests/18/lefdefref.pdf)

**Cell LEF 几何是必要输入，但不是全部规则。** 技术层、vias、轨道起点、spacing tables 等若不在文件中，必须由 tech LEF/规则配置提供。暂时缺失时可以使用命名的简化规则集或参数区间计算，结果明确标为对应简化模型；不阻止建模，也不声称覆盖未知规则。

### 候选接入不是一个点，而是一个可检查的方案

候选 `a` 保存坐标、层、允许方向、via 类型、上下层 enclosure、cut 形状，以及必要的短接入段。先生成，再判定合法性。

对矩形 via enclosure，合法中心位置可由 pin polygon 对 enclosure 做几何侵蚀得到。例如 `P ⊖ E_v` 表示把 via enclosure 平移到中心位置后仍完全包含于 pin 的位置集合。再与声明网格及障碍的排斥区结合检查。上层金属和 cut 也必须检查。

这种几何运算是计算原语，不是所有 DRC 的通用替代：EOL、parallel-run-length、same/different-net、多图形及 patterning 条件可能需要专门规则判定器。每次接受/拒绝都应保存对应规则及输入形状。

不能只保留 on-track 交点。若策略允许，shape-center、enclosure-boundary、half-track 等候选也可能必要；PAO 已明确给出这些候选类型，并以 master、orientation、track offset 区分 unique instances。[PAO 原文，II–III 节](https://vlsicad.ucsd.edu/Publications/Conferences/377/c377.pdf)

### 几何怎样直接进入概率

固定目标 cell 的朝向、track phase 和候选集合，令 `Ω` 是邻居的一组合法位姿。对候选 `a`，从 pin/via enclosure、邻居形状和 DRC 排斥区直接计算：

候选集合先剔除固定目标/技术条件下已不合法的方案；等价地，可把这些方案的阻挡集合设为整个 `Ω`，不能让它们成为虚假的成功入口。

`B_a = {z∈Ω : 位姿 z 下候选 a 被阻挡或违反已声明规则}`。

对位姿分布 `q`，一个 pin 的所有候选都失败，当且仅当位姿落入所有 `B_a` 的交集，因此：

`P_pin_AP = 1 − μ_q(∩_(a∈A_p) B_a)`。

这里 `μ_q` 是概率质量；均匀离散参考分布下，就是“交集中合法位姿数量 / 全部合法位姿数量”。在声明为连续均匀的数学模型中可以用相应测度比，但真实 placement site 是离散的，不能默认改成连续面积。该公式在固定候选和给定模型内精确，不需要拟合一个经验权重。

这个表达直接把 **pin location、pin/via geometry、间距排斥区、邻居相对位置与可替代入口** 连接到了概率。多个 AP 容易被同一个邻居同时遮挡时，`B_a` 高度重合，额外 AP 带来的冗余很小；阻挡位姿集合互补时，冗余更有效。若某 pin 没有候选，定义其失败位姿集合为整个 `Ω`，成功率为零。

例如有 8 个等权合法位姿，两个 AP 各在其中 2 个位姿被挡。若二者都在 `{0,1}` 被挡，pin 成功率为 75%；若分别在 `{0,1}` 和 `{2,3}` 被挡，pin 成功率为 100%。两种情况都各有两个 AP，且每个 AP 的成功率都是 75%。这里的阻挡集合是说明性构造，实际集合必须从输入几何计算。

更一般的朝向、相位和多个邻居变化，可以分条件计算后用全概率公式合并。对整个 cell，则必须在同一位姿中进一步检查联合资源约束，不能将各 pin 的上述概率相乘。这提供了从几何集合运算到概率、再到联合可行性的一条直接计算路径。

### 从落点扩展到逃逸路径

建立局部分层 routing graph：顶点是候选连接位置，边表示合法金属段或层间 via，冲突约束描述不同边/路径不能同时使用的情况。每条路径都必须从 pin 的合法候选出发。

出口 `Γ` 应是明确的 halo 边界或上层 routing interface；不强制等于 cell 的二维外框，因为外部布线可从上层经过 cell。出口的位置、允许层、方向、可用容量、halo 范围与路径预算必须记录。扩大 halo 或放开上层可能让结果改变，因此这些参数是模型身份的一部分。

不同网络构成多 commodity 的路径问题；同网端点可按真实语义合并为树。一般 max-flow/min-cut 可以提供容量瓶颈或必要条件，但不能代替包含多网络、via 冲突和复杂 DRC 的联合可行性求解。

## 不把资源竞争错误地当成独立事件

用二值变量 `x[p,a]` 表示是否为连接义务 `p` 选接入/逃逸方案 `a`。基础约束包括：

`Σ_(a∈A_p(z)) x[p,a] = 1`

`x[p,a] + x[r,b] ≤ 1`，若两个方案互斥；

以及资源容量、连通性、网络合并和不可用成对关系表达的高阶规则。

对每个环境，可以用完整小规模枚举、SAT/SMT、整数规划或有证明边界的搜索判断联合可行性。使用哪种求解器不改变成功事件；候选裁剪和超时却会改变能证明什么，必须显式处理。

分别命名 `P_pin_AP`（存在合法落点）与 `P_pin_escape`（存在到指定出口的完整路径）；一个 pin 有 AP 但无法逃逸是允许的。后者是其路径成功事件的并集：

`P_pin_escape = P(至少一条合法路径可用) = P(∨_a E_a)`。

`1 − ∏_a(1 − P(E_a))` 只有在路径事件相互独立时才成立。共享一个 via slot、同一 narrow channel 或同一邻居遮挡的路径显然相关。方案数增加不等于独立冗余增加。

更直接的第一性原理表达是：先让环境生成资源状态 `Y`，再计算“存在一个联合方案，其所需资源均可用”的布尔函数 `F_c(Y,z)`。小模型可通过枚举、BDD 或加权模型计数精确积分；大模型用有权重的场景采样近似。模型计数必须使用真实声明的联合概率分解，不能因为使用 BDD 就默认资源独立。

### 一个精确反例

以下是数学构造，不是目标库实测：两个不同网络 pin 各有上下两条逃逸通道可选，每条通道只能容纳其中一个网络。上下通道各以 25% 概率被背景路径阻断，二者阻断相互独立，但其状态对两个 pin 是共享的。

| 环境 | 概率 | 单独考察任一 pin | 两个 pin 同时接入 |
| --- | --- | --- | --- |
| 上下都通 | 56.25% | 可接 | 可接 |
| 只上通 | 18.75% | 可接 | 不可同时接 |
| 只下通 | 18.75% | 可接 | 不可同时接 |
| 上下都堵 | 6.25% | 不可接 | 不可接 |

每个 pin 的单独成功概率为 `1 − 0.25² = 93.75%`，cell 联合成功率却只有 `0.75² = 56.25%`。把两个 pin 的概率相乘会得到 `87.890625%`，显著高估。

如果另一种几何让两个 pin 各自有两条完全不共享的通道，在同样阻断假设下，它们的联合成功率为 `87.890625%`。**两种 cell 每个 pin 的 AP 数相同、单 pin 成功率相同，联合失败风险仍然不同。** 区别来自几何形成的共享资源与容量。

## 将 placement 和 routing 算法放到正确位置

### Placement 决定环境分布

placement/ legalization 改变位置、邻居、row、padding 和轨道相位。使用 wirelength、timing、density、congestion 或 pin-aware 目标时，形成的 `q(z|c)` 不同。因此不应从全库均匀抽邻居后，就把结果称为某个真实设计的概率。

第一版建议保留三类独立 profile：

| Profile | 定义 | 概率含义 |
| --- | --- | --- |
| 几何参考 | 有限合法朝向/相位、声明的邻接组合及权重，低外部占用 | 同一评价协议下可复现的库比较 |
| 压力曲线 | 分档增加合法背景路径、不同方向需求或邻接密度 | 对指定压力机制的条件成功率 |
| 应用分布 | 来自指定设计族/placement policy 的实际联合分布 | 对该设计族的预测，需留出验证 |

所有库间比较必须公开相同或明确可比的 `M/D` profile，例如所有信号 pin 活跃且属于不同网络；减少活跃 pin 或允许更多同网合并本身就可能提高概率，不能解释为几何改善。

没有数据时，均匀权重是一个公开参考约定，不是“真实世界无偏分布”。可给出多个合理先验或权重区间的结果，而不是把未知权重压成一个看似精确的百分数。对于合法状态有限且约束已声明的情况，最大熵分布可以作为一个命名参考，但仍不能证明其代表产品 workload。

### Routing 决定需求、资源占用和搜索成功

粗粒度 global routing/Steiner topology 可提供出口方向及区域需求，但其容量图不能直接证明细粒度 pin access。详细 routing 则在离散轨道和 via 约束下进行路径搜索，受网络顺序、拥塞代价、rip-up/reroute 与计算预算影响。这些因素应作为需求/占用生成或明确的代理路由策略，而非随意乘上的“router 系数”。[TritonRoute 原文](https://vlsicad.ucsd.edu/Publications/Journals/j133.pdf)

背景占用建议由连续路径、共享拥塞区及 PDN 模板生成，维持空间相关性；避免给每个 AP 独立抛硬币来模拟真实背景。物理上不可能的随机 via/线段组合不能作为合法基准环境。

一个简单代理策略可以按声明顺序做 maze/A* 搜索，以长度、via 数、转弯和占用价格定义代价，再允许有限次数 rip-up。这些代价是算法选择参数，**不是概率**。随机顺序或 tie-break 的分布也要记录；没有随机因素的策略在固定环境上只有成功或失败。

### 区分有解与找到解

在完全相同的规则、候选、需求和出口下定义嵌套事件：

- `A`：每个活跃连接义务分别至少存在一个合法 AP；“分别存在”不假定概率独立。
- `B`：存在同时合法的所有 landing/stub 选择。
- `C`：存在含这些 landing/stub 的联合逃逸路径。
- `D_cert`：指定算法在预算内返回路径，且通过同一 `C` 判据的独立检查。

则 `D_cert ⊆ C ⊆ B ⊆ A`，可以用条件概率链式分解：

`P(D_cert) = P(A) · P(B|A) · P(C|B) · P(D_cert|C)`。

这是事件定义保证的链式法则，不是假定各阶段独立。当前核心指标为 `P(C)`；`P(D_cert)` 衡量给定策略/预算下的成功率。若前一事件概率为零，后续条件概率报“不适用”，不计算 `0/0`。

第二个精确反例：A 可走 U/V，B 只能走 U，两条通道都可用。存在合法解 A→V、B→U，因此 `P(C)=1`。一个不回溯的策略若随机决定先处理哪个 pin、并让 A 优先选 U，则成功率为 50%。这个 50% 反映策略能力，不能说几何上有 50% 概率无解。

## 评价指标体系

概率是主指标；几何数量、原因与敏感性用来解释概率，而不是与概率相加成总分。

| 层次 | 指标 | 定义或用途 |
| --- | --- | --- |
| Pin | 合法落点概率 | `P_pin_AP=P(A_p)`；`A_p` 表示该 pin 至少存在一个合法 AP |
| Pin | 单 pin 逃逸概率 | `P_pin_escape=P(该 pin 存在到声明出口的路径)`；不代表其他 pin 同时被满足 |
| Cell | 联合接入成功/失败概率 | `P(C)` 与 `1−P(C)`；核心输出 |
| Cell | landing 联合成功率 | `P(B)`；区分入口冲突与外围逃逸瓶颈 |
| 原因 | 无 AP 风险 | cell 级为 `P(A^c)`，即至少一个活跃义务没有 AP；pin 级另报 `P(A_p^c)` |
| 原因 | 联合 landing 冲突风险 | `P(A∩B^c)`；各自有入口但无法同时选择 |
| 原因 | 逃逸失败风险 | `P(B∩C^c)`；入口可选但外围路径/容量不足 |
| 算法 | 搜索失败差距 | `P(C∩D_cert^c)`；需要可行性证据，不由原始 router fail 直接推断 |
| 影响 | 未满足义务的最小数量分布 | 每场景求最大可满足集合 `K(z)`，报告 `|P_active(z)|−K(z)`；未知最优值保留界 |
| 冗余 | 资源多样性与脆弱资源 | 独立出口、共享 cut/track/via 资源、移除某资源造成的成功率变化 |
| 邻域 | 邻接兼容矩阵 | 按 neighbor、orientation、gap、phase 条件化的 `P(C|context)`；不仅取平均 |
| 方向 | 方向/层条件成功率 | 给定 escape demand 的成功率；可揭示仅能单方向接入的 pin |
| 压力 | 成功率响应曲线 | `P(C|ρ, direction, PDN, gap)`；`ρ` 必须有具体占用定义 |
| 改善 | 配对干预收益 | 同一背景/需求下改变一个允许因素的 `ΔP`，附物理与电气副作用边界 |
| 稳健性 | profile 敏感性 | 参考分布/规则区间改变时概率的范围、排序是否翻转 |
| 可信度 | 求解未知质量、统计区间、规则覆盖 | 三者分别展示；没有证据时不用统一置信分数掩盖 |

前三类物理失败原因是互斥分解：`P(C^c)=P(A^c)+P(A∩B^c)+P(B∩C^c)`。它们按已声明阶段解释失败；更细的根因可能交互，不能把“去掉任一障碍后的改善”都相加，否则重复归因。

`P(A)` 是所有单 pin 存在事件的交集概率；`P(B)` 才是同一组方案同时可行的概率。这一差别不能靠相关系数修补，必须保留联合约束。

压力曲线可以报告“达到某风险阈值所对应的压力”，但阈值由使用场景决定。只有通过嵌套增加占用、且固定其他条件时，才要求可行概率单调不增；任意改变场景分布不具有该单调保证。

### 怎样回答某个 cell 是否存在问题

一个有明确几何/规则证据的失败场景，可以证明该 cell 在该场景下存在问题；其是否值得优先修改，由该场景的概率质量和失败后果决定。应区分“已证场景失败”“模型预测高风险”和“规则/求解未知”。未来再按应用代价与实测校准制定风险阈值。

有限参考分布下概率为零，只能说明这个分布覆盖的条件内没有失败，不能证明所有实际放置都安全。相反，一个特意加压的场景失败，也不能直接把 cell 定性为不合格。输出最坏反例、概率及 profile 能同时回答可能性、频率与适用范围。

## 不确定性和可证明边界

每个场景至少返回 `PASS`、`PROVEN_FAIL` 或 `UNKNOWN`，另保留格式/规则输入错误。`PASS` 必须携带 `certified_under_theta`；简化规则下的 witness 只证明简化模型通过，规则覆盖未经资格确认时不能展示成已通过真实物理验证。求解超时、候选截断、未知规则不能算失败或通过。

- 一个解只有经原判据检查的 witness 才能证明通过。保守候选子集找到的 witness 可以建立下界；子集找不到解不能证明完整问题失败。
- 只有明确证明原可行集合包含在放松集合中，放松问题的**已证明无解**才可证明原问题无解。例如有条件的容量 cut 下界；多 commodity、同网合并和出口义务不得被偷偷改变。
- 规则缺失不自动形成可靠上界。必须证明所用规则确实是原规则的放松，且没有误读单位、PORT/OBS、via 或候选语义。

对完整枚举且权重总和为 1 的有限场景分布，设通过、证明失败和未知的质量为 `W_P,W_F,W_U`，则：

`W_P ≤ P(C) ≤ W_P + W_U`。

该范围只覆盖已声明 `θ,q` 下的求解未知。例如 `0.70/0.20/0.10` 对应 `[0.70,0.80]`。它不是模型真实准确率的置信区间。

对大规模 Monte Carlo，应另外报告采样误差；普通二项区间仅适用于相应 IID 条件。主动采样/重要性采样需要正确权重，分层采样按分层设计估计误差。重复同一 placement 的多个 seed 也不能伪装成独立环境样本。

如果 `q` 和 `θ` 本身只能落在声明集合中，可以报告 `inf_(q,θ) E_q[F]` 与 `sup_(q,θ) E_q[F]` 的敏感性包络。它是对假设集合的稳健范围；未经构造的全局最坏情况与拍脑袋上下限不属于此定义。

## 计算与扩展路线

1. 对 master/合法朝向/track phase 生成物理候选；按输入和规则 hash 缓存，保留拒绝原因。
2. 生成合法邻域与背景路径场景，保存权重和随机种子；先枚举小状态空间。
3. 计算 `A/B/C`，小问题精确求解，大问题用 witness 和已证失败建立界；把预算优先分配给未知且概率质量较大的场景。
4. 汇总概率、原因和 profile 曲线；记录每个结论可回放的场景与几何证据。
5. 如需算法层，再增加明确的代理路由策略，报告 `D_cert`；不能反过来用一次启发式失败定义 `C=0`。

相同或近似几何的组合可减少计算，但只有证明其在规则、需求、出口和概率质量上等价时才可无损合并。区域平均或相似签名只是近似，不应宣称精确概率。这里的设计不要求先实现一个完整工业 router，局部模型的范围由 halo、候选、规则和资源预算控制。

## 未来怎样校准，而不破坏概率语义

真实物理设计环境具备后，按三层收集证据：

| 校准层 | 收集内容 | 能修正什么 |
| --- | --- | --- |
| 几何/规则层 | reference AP、via、DRC 原因与具体 witness，视图及规则版本 | 候选生成、规则覆盖和错误解释 |
| 环境层 | 实例朝向、track phase、邻居、gap、PDN、需求与实际 routing occupancy | `q` 的联合分布及参考 profile 的代表性 |
| 算法层 | 版本、顺序、guide、搜索预算、重试及失败原因 | `P(D_cert|C,z)` 或目标工具成功预测，不冒充物理无解概率 |

单次 post-route 失败不能识别 `C=0`：可能只是搜索未找到解。成功路径在局部裁剪和同一语义检查后可提供正 witness；失败样本需要更强局部求解、放松问题证明或标为未知。标签事件不一致时不能直接校准同一个概率。

先固定事件、profile、规则和分组留出集，再用 Brier score/log loss、reliability diagram 和适当置信区间检查概率校准；这些监督指标只用于有匹配事件标签的输出。排序效果另用 precision/recall、PR-AUC 及漏报代价评价。`C` 的未知标签不能被强行二值化。

按 design、library revision、cell/context family 分组留出，防止近重复几何泄漏。实际 placement 中被选用的 cell 和幸存位置带有选择偏差；对“改变 cell 后”的推断需要重新采样或明确干预分布，不能只重用幸存实例的统计。

校准优先修正实际偏差来源：缺规则就补规则，邻居分布错就改 `q`，算法失败就改算法层。不能只加一个任意 sigmoid 把所有分数挤进 `[0,1]` 后称作物理概率。若使用统计校准映射，也要保留原概率、目标事件、数据范围与校准版本。

## 可现在验证的数学要求

以下是模型验证要求，不是产品测试完成声明：

- 几何/规则/网格同时做等价单位或坐标变换时，结果保持；只移动 cell 相对固定网格时可以变化。
- 新增一个原规则下合法的备选方案且不删除资源，不降低可行性。改变 pin 形状可能阻挡其他网络，不受这条单调性保证。
- 在同一耦合样本中只增加固定障碍、其他语义不变，不提高可行性。
- 完整小枚举概率归一；共享通道反例与不共享通道对照符合解析值。
- 算法顺序反例中 `C` 与 `D_cert` 不混淆。
- `P(C) ≤ P(B) ≤ P(A) ≤ 1`；增加候选/求解预算只收紧适当证明界，不把未知自动转成失败。

本轮精确枚举结果见[数学检查记录](pin-access-probability-math-checks.json)。检查的是概率定义和反例算术，没有使用 LEF 或 P&R 数据，不能作为几何模型准确性的证明。

## 与已有研究的关系和交付边界

PAO 支持从 master/orientation/track-offset、DRC-aware AP 到联合模式的确定性结构；Cell-Flex 支持场景、PDN 和资源自由度的重要性。本文进一步指定环境测度、嵌套事件、概率边界和校准对象，是为本项目提出的模型设计，不声称是已发表的新方法。[PAO](https://vlsicad.ucsd.edu/Publications/Conferences/377/c377.pdf)；[Cell-Flex 作者报告](https://ispd.cc/ispd2026/slides/2025/protected/11_1_slides.pdf)

NVCell 2 也使用“routability probability”表述，但其相关章节从已路由的未连接位置与拥塞构造平滑训练标签，应用于 cell 内部布局生成。它不能直接作为“仅凭外部 LEF 的接入成功概率”公式，也不能提供本模型的未校准准确率。[NVCell 2，ISPD 2023，3.2 节](https://mik226.github.io/HoHFK23.pdf)

Library Insight 的拟议输出是每个 cell 在命名条件下的失败概率/范围、瓶颈 pin、失败原因、邻接与压力响应，以及可验证的改善方向。尚未指定现有代码中的实现接口，不引入新的 Runtime 或事实源。后续实施切片应继续在现有 Pack 方法、物理工具适配和 Data Insight 证据呈现职责内定位。

当前形成的是**模型定义与可证伪的计算路线**。真实库输入、完整物理规则、reference oracle 和概率预测有效性仍未验证；这些缺项不妨碍先用明确假设开展计算实验，但必须随每个概率保留。
