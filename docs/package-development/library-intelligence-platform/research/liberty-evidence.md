# Liberty semantic value map: evidence ledger

Date: 2026-09-22

Scope: Liberty semantics, installed Empyrean Liberty API surface, and the evidence boundary from Library facts to chip-level decisions.

Data handling: no commercial EDA was run; no proprietary Liberty body was copied. Site observations are metadata/interface observations only.

## Claim-to-source ledger

| ID | Claim supported | Source | Class and boundary |
| --- | --- | --- | --- |
| LIB-E01 | The Liberty hierarchy explicitly carries library units, PVT operating conditions, lookup templates, cells, pins, buses/bundles, power/ground pins, timing/power/constraint groups, waveform/current models, LVF data and EM groups. | [Synopsys Liberty Reference Manual R-2020.09](https://zao111222333.github.io/liberty-db/2020.09/reference_manual.html), especially pp. 21–98, 103–217 and 248–372; accessed 2026-09-22. | `STD`. Primary Synopsys-authored manual on a third-party Open Source Liberty mirror. The official [Synopsys documentation gateway](https://www.synopsys.com/support/licensing-installation-computeplatforms/synopsys-documentation.html) is the authoritative distribution route but requires entitled access. Attribute existence does not prove a particular Library populated it correctly. |
| LIB-E02 | Units are semantic, not cosmetic: `time_unit`, `voltage_unit`, `current_unit`, `capacitive_load_unit`, `leakage_power_unit`, threshold and slew definitions change numeric interpretation. Missing leakage units leave values unitless; capacitance has no default if omitted. | Same manual, pp. 22, 27, 33, 35 and threshold/slew sections. | `STD`. The exact legal enum set is release-specific. Consumers must preserve raw token and normalized SI value. |
| LIB-E03 | `operating_conditions` defines process, voltage, temperature and interconnect-tree type; a corner filename is not itself a normative PVT identity. | Same manual, pp. 72–73. | `STD`. Process is partly a scalar/label abstraction; RC corner, device-model deck and statistical population are not established by this group alone. |
| LIB-E04 | `lu_table_template` and specialized templates define axes and sampling grids; NLDM `cell_rise/cell_fall` and transition groups reference them. Table dimensions and value cardinality are deterministically checkable. | Same manual, pp. 65–66 and 348–355. | `STD`. Interpolation/extrapolation policy and tool clipping behavior are not fully established by table syntax alone. |
| LIB-E05 | `function` defines output/inout Boolean behavior; `three_state` defines the high-impedance condition; `ff`, `latch`, and `statetable` encode sequential behavior. | Same manual, pp. 157–161, 217–218, 248–251 and 280. | `STD`. These are abstract functional semantics, not transistor topology, hazards, analog behavior or proof of equivalence to Verilog/SPICE/layout. |
| LIB-E06 | Timing-arc identity is conditional and multi-field: endpoint pin, `related_pin`, `timing_type`, `timing_sense`, `when`, mode and SDF conditions jointly determine meaning. `timing_sense` may be derived from a combinational function, but non-unate and conditional paths need state context. | Same manual, pp. 313–314 and 327–337. | `STD`. Arc matching by only from-pin/to-pin is unsound. `sdf_cond` is an SDF projection and must not be assumed textually identical to Liberty `when`. |
| LIB-E07 | CCS timing uses output-current waveforms/templates and receiver-capacitance models; CCS noise uses current/voltage/noise structures; CCS power can carry PG current waveforms. These hold richer dynamic behavior than scalar capacitance plus NLDM delay tables. | Same manual, pp. 66, 70, 74–75, 82–83, 150–156, 287–292, 316–319 and 352–365; [Synopsys CCS announcement](https://news.synopsys.com/home?item=122638). | `STD` + `VENDOR`. Richer representation does not by itself prove better correlation for every load/interconnect regime. |
| LIB-E08 | ECSM is a distinct current-source model intended to model timing, noise, power and variation, including voltage fluctuation and nonlinear drive effects. It must not be relabeled as CCS merely because both are current-source models. | [Cadence ECSM Library Format](https://www.cadence.com/en_US/home/alliances/standards-and-languages/ecsm-library-format.html), accessed 2026-09-22. | `VENDOR`, official format-owner page. The installed Empyrean wrapper inventory observed here exposes named CCS/CCSN classes, not an independently proven complete ECSM object model. |
| LIB-E09 | Internal power tables represent energy/power per transition under related-pin/condition/mode context; leakage can be cell-default or state/power-rail dependent; dynamic PG-current waveforms are a separate model. | Liberty manual, pp. 150–156, 199–200 and 297–307. | `STD`. Liberty does not provide real workload activity, clock gating residency, IR-drop waveform or package/board loss. |
| LIB-E10 | Minimum pulse width and minimum period may be conditional and power-state/mode aware; setup/hold/recovery/removal and non-sequential checks are timing-arc types, not ordinary propagation delay. | Liberty manual, pp. 311–314 and 330–336. | `STD`. A constraint table cannot be interpreted as delay, and absence can mean unsupported, implicit/default, omitted or invalid—not zero. |
| LIB-E11 | LVF represents per-arc/load/slew parametric variation. Sigma tables describe one-sigma offsets from nominal; moment-based LVF adds mean shift, standard deviation and skewness for asymmetric/biased distributions. The manual explicitly distinguishes parametric OCV from AOCV derates applied across multiple cells/library scope. | Liberty manual, pp. 356–363; [Synopsys unified OCV/LVF announcement](https://news.synopsys.com/2014-09-30-Synopsys-Announces-New-Additions-to-Liberty-to-Significantly-Speed-up-Timing-Closure). | `STD` + `VENDOR`. LVF data is input to statistical timing; it is not a path-yield result. AOCV/POCV/SOCV flows also depend on tool configuration and, for AOCV, path depth/distance derate context not inferable from nominal tables. |
| LIB-E12 | Liberty can express pin-level electromigration lookup models, maximum toggle-rate models, temperature degradation, and lifetime-profile labels; it also has soft-error and critical-area constructs. | Liberty manual, pp. 25–26, 58–59, 127–129 and 292–296. | `STD`. The R-2020.09 manual contains no generic `aging` or `reliability` coordinate. BTI/HCI/device aging sign-off, metal topology, current sharing, thermal history and foundry qualification are not established by Liberty alone. |
| LIB-E13 | Installed Empyrean material declares three modules: `tmlib` read/query/write, `evaluator` cell PPA evaluation, and `corner` multi-file management; demos expose parser, round-trip output, NLDM/CCS/receiver-cap data, evaluators, plotting and corner linking. | Site-local `/data/eda/software/eda_tools/empyrean/libapi-2026.master.c68db94/API/README` and `API/demo/*.py`, read through SSH on 2026-09-22. | `SITE`, vendor-authored installed material. Interface declaration only; no commercial EDA or API execution was performed in this slice. |
| LIB-E14 | The generated wrapper exposes generic group/attribute traversal plus specialized Library/Cell/Pin/Bus/Bundle/PgPin/Timing/InternalPower/ReceiverCap/Leakage/FF/Latch/StateTable/OperatingCondition/Template objects, NLDM interpolation and CCS data traversal. The evaluator declares POCV switches and sigma settings. | Site-local `API/tmlib.py`, `API/evaluator.py`, and `API/corner.py`, read-only AST/interface inventory on 2026-09-22. | `SITE`. SWIG/native interfaces may change; generic traversal may be needed where no specialized class exists. Declared `interpolate()` and POCV controls are not validated behavior. |
| LIB-E15 | The installed fixture currently imports and parses far enough to obtain a handle, then exits 139 at `lib.name()` in the qualified Python 3.7/`edarun` attempt. Therefore no API query or write behavior is qualified for product use. | [environment-qualification.md](../environment-qualification.md) and [evidence-ledger.md](../evidence-ledger.md), observations dated 2026-09-22. | `PRODUCT`. Reproduced boundary, not diagnosed root cause. This task did not rerun or debug it. |
| LIB-E16 | A Library view can be internally parseable while inconsistent with Verilog, SPICE/CDL or extracted layout; wrong release/symlink consumption and mutually consistent bad SPICE/layout can escape ordinary equivalence/LVS. | [Cadence: Verifying Final Netlist / LVR](https://community.cadence.com/cadence_technology_forums/f/logic-design/2465/tip-of-the-month-verifying-final-netlist), accessed 2026-09-22. | `COUNTER`, official Cadence technical forum article. ## Integrity checks actually performed

- Opened and semantically inspected the cited public HTML sources in `ego-browser` on 2026-09-22. The Synopsys manual mirror exposed the named sections and page text; the official documentation gateway was separately identified.
- Inspected installed Empyrean README, demos and wrapper method declarations through read-only SSH. No native module was imported and no commercial tool or license was invoked.
- Cross-checked every requested topic against the value-map coverage checklist with `rg`; checked that cited relative repository links resolve.
- Human semantic spot-checks covered: units/PVT, timing identity and conditions, CCS/ECSM, power, LVF/AOCV distinction, EM/aging boundary, and Liberty-only counterexample.

## Evidence gaps

1. The entitled, current Synopsys Liberty manual was not available from the public official gateway; R-2020.09 is the primary authored reference used here. Newer grammar/semantics must be version-gated.
2. No installed Empyrean call is qualified. Exact parse preservation, generic-group coverage, interpolation/extrapolation policy, unknown-attribute behavior and write round-trip remain unproven.
3. No representative real Library was queried, so the actual presence/absence distribution of LVF, CCS, EM, noise, receiver-cap and power-waveform data is unknown.
4. No golden SPICE, characterization recipe, STA readback, design activity, physical database or silicon measurement was joined. All chip-level effects remain proposed conversion chains, not measured outcomes.
5. ECSM syntax was not mapped attribute-by-attribute because the installed wrapper does not yet prove an ECSM-specific surface; the product must preserve unknown groups generically rather than pretend CCS equivalence.

Research stopped because another attribute search would not change the immediate product priorities: first qualify a lossless, versioned extraction boundary; then prove design-conditioned delta triage. The unresolved items are qualification or corroboration work, not missing prose.
