# Custom Cell Fmax DTCO V5.2.3 layout-family parallel release

Date: 2026-09-20
Version: `5.2.3`
Method digest: `979fff259e85951513b748dbd1e26325417927e27ecc219941b9a83b15d71100`

Trial.17 materialized 50 Boolean Cell Demands. Each demand expands into
D1/D2/D4/D6/D8, so the existing `layout` stage scheduled 250 physical
abstractions. The implementation iterated every Cell serially and invoked the
same topology placement solver five times per family. After roughly 93 minutes
it had produced 192 LEFs and was still healthy; the cost was real but most of
the repeated solver work was unnecessary for a Mock Library.

V5.2.3 retains all five physical LEFs and their distinct drive-scaled geometry.
It changes only how the existing layout stage obtains the topology:

- D1 runs the real topology placement once per Boolean family;
- D2/D4/D6/D8 reuse the verified D1 column count and expand site/pin geometry by
  the existing drive scale;
- up to five independent Boolean families execute concurrently;
- the record still carries one command, log, exit, LEF and metadata artifact per
  physical Cell, and derived metadata names its D1 placement source.

For 50 single-output demands, placement-solver calls fall from 250 to 50 and
200 variants reuse topology. A maximum of five workers makes the solver portion
up to 25 times shorter in the ideal case; container startup, derived LEF writing
and unequal family runtimes reduce the realized gain.

- a deterministic batch test proves one placement per family, exact
  D1/D2/D4/D6/D8 outputs, reused D1 columns and overlap between independent D1
  placements;

- Pack contract tests: 26/26 passed;

The optimized stage has not yet run on the real Site. Trial.17 remains on the
sealed 5.2.2 method and is allowed to finish generation 1 so its approximately
192 completed layouts are not discarded. Before generation 2 layout, it will
pause and preserve the matched result. Trial.18 will validate this optimization
with one new 5.2.3 Campaign.
