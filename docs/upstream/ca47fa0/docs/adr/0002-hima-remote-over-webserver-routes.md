# Expose Hima's host-to-browser interface as HTTP routes on the dsh web server, not as a Typert remote service

The workbench needs the ledger's runs, records, and verdicts in the browser. DeepSeek Harness's own Host-to-Client mechanism, Typert remote services with `@Remote` methods, is generated by the dsh repository's build (`DSH_BUILD_FACE host` plus the `api-remotes` assembly) and has no documented path for an out-of-tree bundle; the research in `docs/research/2026-09-08-dsh-architecture-and-integration.md` §7 rates it the single most build-coupled seam. We decided that Hima's remote interface is a set of HTTP routes registered through the documented `ctx.webServer.register` seam of `@deepseek-ai/dsh-host-webserver`, all under one namespace `/hima/api/`, each handler first calling the web app's own `connection.requestRejection` so the routes sit behind the same Host and Origin fence and signed session cookie as dsh's `/api`. Both sides are Hima-owned: `remote.ts` on the host and `client/api.ts` in the browser, marked as the wrapped seam per ADR-0001.

## Considered options

- **Typert remote service.** Rejected for now: reproducing the repository-only generator step out of tree is undocumented, and the previous attempt lost days to exactly that build coupling. Revisit when dsh documents an out-of-tree Remote contribution.
- **A separate Hima web server.** Rejected: a second listener means a second auth boundary and a second thing for a customer's CAD to expose.

## Consequences

- The browser module talks to the host with `fetch` against `/hima/api/...`; errors are JSON `{ error: { code, message } }` with `hima/*` codes. If dsh later changes its route or connection seams, the blast radius is `remote.ts` and `client/api.ts`.
- `POST /hima/api/observe` is part of the namespace so the workbench and tests can create runs over HTTP with the same observe operation the command and tool use.
- The client bundle is built out of tree into dsh's loader envelope with React and the dsh baseline as externals; the build script owns that envelope and is the second place a dsh browser-side change would land.
