# bool2cmos

Synthesize a **CMOS transistor network** (SPICE subckt) from a Boolean function.

Implements the method of *"Generation of Series-Parallel Multilevel Transistor
Networks Based on BDDs"* (Wu / Liu / Zeng, HiSilicon): ROBDD construction,
ROBDD → pull-up/pull-down mapping, bridge detection and elimination, network
optimisation, and multilevel decomposition under series-stack constraints.

**Multi-output cells (§7) are an original extension — the paper covers a single
BDD root only.**

Pure Python 3, no dependencies (the ROBDD package is included). `pytest` is
needed only to run the test suite.

```bash
bool2cmos --function "!(A&B)" --inputs A,B --output ZN \
          --pdk sky130 --cell-name MY_NAND2 --out my_nand2.sp

# one cell, two outputs, sharing logic where it is physically legal
bool2cmos --function "A^B^CI"              --output S  \
          --function "(A&B)|(B&CI)|(A&CI)" --output CO \
          --inputs A,B,CI --pdk tsmc28 --cell-name MY_FA1
```

```python
from bool2cmos import synthesize_function, synthesize_multi

r = synthesize_function("!((A1 A2)+B)", ["A1", "A2", "B"], "ZN", pdk="tsmc28")
print(r.spice)          # SPICE subckt
print(r.metadata)       # device count, levels, phases, verification verdict
assert r.verdict.ok     # symbolic proof of correctness

m = synthesize_multi(
    [("S", "A^B^CI"), ("CO", "(A&B)|(B&CI)|(A&CI)")],
    ["A", "B", "CI"], pdk="tsmc28", cell_name="MY_FA1",
)
assert m.verdict.ok
print(m.metadata["sharing"]["verdict"])       # SHARED_INTERNAL_LOGIC
print(m.metadata["sharing"]["devices_saved"]) # 10, vs synthesizing separately
```

## 1. The algorithm

### 1.1 Function → ROBDD

The Liberty-style expression is parsed, evaluated into a truth table, and
built into a reduced ordered BDD (`bool2cmos/bdd.py`). Variable ordering is
searched: all `n!` orders for `n ≤ 6`, a seeded random sample above that. The
cheapest orders by node count are then fully synthesized and scored by *actual
device count*, not by BDD size.

### 1.2 ROBDD → pull-down / pull-up networks (`synth.bdd_to_networks`)

Exactly as in the paper:

# celluzi — SKY130 AI-Driven Custom-Cell PPA Optimization

Implements the North Star loop in [docs/sky130_customcell_north_star_plan.md](docs/sky130_customcell_north_star_plan.md):
**detect** where a design would benefit from bespoke standard cells → **generate + characterize**
those cells on SKY130 → **integrate** them into the flow → **re-run** → prove a measurable
**PPA delta** vs. a frozen golden baseline, in a closed, repeatable loop.

## Where things run
- **Toolchain:** IIC-OSIC-TOOLS (rootless podman) on the `linglong` EDA server — OpenROAD/ORFS,
  Yosys, Magic, KLayout, Netgen, ngspice, OpenSTA, CharLib + the SKY130 PDK. Pinned image:
  `docker.io/hpretl/iic-osic-tools:2026.06` (see `env/tool-versions.lock`).
- This repo is **authored locally** and synced to `/data/eda/project/celluzi` on the server,
  where the heavy artifacts (ORFS, PDK, run outputs) live and are **not** tracked in git.
- No git remote / no push — the server's outbound access is gated by its owner.

## Milestones (plan §4)
| | Goal | State |
|---|---|---|
| **M0** | Environment + frozen golden baseline | ✅ **done** — aes DRC-clean, golden frozen |
| M1 | Detect custom-cell opportunities (CircuitOps + OpenSTA) | **next** |
| M2 | Generate one cell (known-cell calibration first) | todo |
| M3 | Close the loop — measured PPA delta | todo |
| M4 | Scale & automate | todo |
