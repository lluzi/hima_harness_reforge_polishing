# U6：统一 DBOS 执行与控制

状态：U6 已完成实现、独立复核与本地集成验证。U7–U10 尚未完成。

本单元让新 Run 经同一个 DBOS 解释器执行 task、sequence、choice、parallel、repeat 和已声明的附加工作。PostgreSQL 保存当前控制、执行身份、结果、资源与原始证据；旧 Ledger 不决定新 Run 的下一步。业务 owner 负责业务决策，已验证结果按方法自动交接。

## 已取得的集成证据

- 统一构建、完整类型检查、接口标记和架构边界检查通过；测试清单 162 个文件，各归组一次。
- 15 个相关测试文件：104/104 PASS，607.629 秒，37 次真实本地 Host 启动，零 SSH。真实模型 API、桌面窗口和 EDA 不在这组验证内。最后一个内部 Team 发送检查修正后，重新构建、完整类型检查通过；三个相关原生用例 3/3 PASS，36.448 秒、3 次 Host 启动、零 SSH。
- 实际 Host 重启覆盖原始暂停、方法冻结、已提交/已提交前外部操作、动态决定与修订。新的修订中断证明保留同一 command、revision、deadline、workflow 和未受影响的 C；仅一个 ready、一个 writer、一次源文件写入，无 ERROR workflow。
- 真实 Host 反例证明：未授权孙代理原先可以写文件；修复后工具和模型请求受约束，暂停、handoff、取消不能解除该约束，独立 Side Talk 和合法原生任务仍可用。
- 单个会话恢复失败不阻止另一个会话恢复、启动命令和取消原任务。并发 cleanup 使用同一个已证实停止记录；错误身份、未关闭资源和缺失原始物理证明仍拒绝。

完整日志保留于 `.hima-tmp/dbos-migration/u6-review-fixes/`。`integrated-matrix.log`、`integrated-build.log`、`integrated-types.log` 及修正后的静态检查日志记录本轮结果；104 例冻结构建与最后单项修正后的三个用例分别保留构建身份，不混记为一次全量运行。

## 测量与限制

八秒等待样本的持久化记录由 757 条降到 70 条；这是两小时预算下的短样本，不是两小时 WAL、磁盘增长或 p95 测量。实际 ATCS 方法含 350 个文件、5,561,004 字节；一次序列化快照约 7.45 MB，扫描、哈希与序列化测得 60.99 ms，未测该样本的 PostgreSQL 写入延迟。

原先一次 optional abandonment 的 Goal 状态异常未能归因。原失败保留，三个精确时序边界已通过；不声称重复运行修复了它。随后独立复现并修复了并发停止证明冲突，但没有证据将两次问题视为同一根因。

准备阶段没有发出写入时，取消可以明确关闭并保留客户原文件；写入后失去完成证明时保留部分内容和 unknown，跨重启也不凭“这次没有写入”推断原工作已结束。缺少当前 Site/Permit 时，尚在运行的 Reader 不能被当作已证实停止。

本记录不证明 App/Guide 正常产品路径、ATCS 完整 dry route、两平台分发或真实 Timing 修复。对应 U7–U10 继续执行；执行成功、Goal、迁移验收和物理采用范围分别判断。
