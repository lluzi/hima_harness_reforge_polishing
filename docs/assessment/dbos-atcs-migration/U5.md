# U5: finite flow compilation and authoring

Issue: [#88](https://github.com/lluzi/hima_harness_reforge_polishing/issues/88). This unit compiles new and supported legacy Pack declarations into immutable `hima-flow-ir/1`. Workflow execution and full author TEST/RELEASE run qualification follow in U6–U10.

## Behavior

`hima-flow/1` has task, sequence, choice, parallel and repeat. Business input sources, schema versions, named branch results, repeat carry and diagnostic return bindings are explicit. Choices cover committed enums; schema references stay inside immutable Pack bytes. A flow with no Strategy knobs can omit them. Runtime identity is not author-written. Historical method bytes and user assets remain intact.

Legacy Act/Reader/Judge/Explore/Wait, fork, loop, growth, Workshop and Team declarations lower into the same IR with their original adapter data. Legacy root/local Wait fallback, opened-loop entries, fork shared joins and revisit carry are preserved. Compilation does not retain a second scheduler or prove execution of those adapters.

Author instructions distinguish the new grammar from legacy bindings. Native Workshop binding is currently documented as legacy-only, rather than inventing a new task adapter. Runtime schema checking stays inside task handoffs; a JSON-only method does not require extra Reader/Judge/Wait stages. Parallel optionality governs required results, not whether a branch runs. A diagnostic requirement is expressed once, as its declared extension or choice.

## Execution handoff

U6 executes IR, not the task-only compatibility display graph. Dependency invalidation must inspect routing selectors, repeat carry/stop and extensions in addition to ordinary input edges. A repeat selects its exit entry from the committed current-iteration result and retains original Run budget. U4/U6 still own adapters, legacy business-result validation and resource closure. U8/U10 still own the actual ATCS method and its result; this unit makes no claim of timing improvement or completed migration.
