# U1: task data contract

Issue: [#84](https://github.com/lluzi/hima_harness_reforge_polishing/issues/84). Scope: the shared task input/output boundary and the accepted responsibility change in ADR-0018. DBOS scheduling, database lifecycle, adapters, GUI and ATCS execution are not qualified by this unit.

Implementation and independent review use Codex gpt-6.1-sol / high with fresh bounded contexts. The host owns integration and authoritative verification. Product model calls, Host boots, Electron launches and SSH attempts in the focused tests: zero. Development token use is not measured.

## Changed behavior

All task producers hand off declared JSON Schema 2020-12 business values with artifact provenance and sourced diagnostics. Runtime supplies the result identity. Six execution projection states are separate from business outcomes; accepting schema data cannot claim persisted completion, resource release or Goal met. Accepted data is detached and frozen.

Only Pack-local schema references are admitted. Validation does not coerce values, add defaults, remove fields or run producer-defined keywords. The synchronous boundary explicitly rejects async schemas.

The meaningful red case supplied `$async: true` with an invalid business output. The old synchronous boolean check accepted the returned Promise; the run recorded 11 passes, one missing expected rejection and an unhandled asynchronous validation failure. Independent review then found that Ajv also treats non-boolean truthy `$async` values as async. The existing test was extended to strings/numbers and failed with the expected missing rejection (`async-nonboolean-red.log`). The corrected boundary allows only an absent `$async` or explicit false; ordinary and explicit-false positive fixtures pass. Root and local declarations use the same check.

Existing ignored Finder metadata at `packages/.DS_Store` made the boundary scanner try to read `.DS_Store/src`. The host preserved that file under `.hima-tmp/dbos-migration/evidence/packages-finder.DS_Store` and reran the unchanged checker successfully. No product checker workaround was added.

Detailed local logs are in `.hima-tmp/dbos-migration/u1/`: `async-red.log`, `green.log`, `host-verified.log`, `host-build.log` and `host-typecheck.log`. They contain no product credentials. The tests themselves retain the falsifier in version control.

## Limits

Artifact metadata validation does not verify artifact bytes; the adapter unit must collect and verify them. Producer-shape fixtures prove the common data protocol, not command/model/engineering adapter execution. Database commit, resource quiescence, flow compilation, product display and live timing conclusions remain later-unit obligations. No extra scheduler, execution mode or retry/fallback was introduced.
