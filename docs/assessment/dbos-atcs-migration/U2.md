# U2: local PostgreSQL lifecycle

Issue: [#85](https://github.com/lluzi/hima_harness_reforge_polishing/issues/85). This unit gives the existing Host ownership of a private PostgreSQL 16.15 cluster and connects its lifecycle to Desktop and native packaging. DBOS registration and execution follow in U3.

Codex implementation, simplification and review used fresh gpt-6.1-sol / high sessions. The eight-lens review also consumed an independent Claude Opus 5.5 result (requested high; actual effort unavailable). Parent owns integration and Git. These lifecycle tests use zero product model calls and zero SSH/EDA attempts; development tokens are unmeasured.

## Behavior

Each Home has private data, 0600 random credentials, loopback SCRAM connections, application/system databases and a persisted identity. Reclaim checks process, data path, port and SQL identity; concurrent claim/reclaim leaves one owner. Unknown startup or shutdown retains the original state. Native staging includes bin/lib/share, linked dependency inventory, file hashes and the PostgreSQL copyright notice. Mac install names and Linux RUNPATH are relocated without requiring Docker on customer machines.

Ordinary window close retains the Host. Explicit exit drains existing services before stopping PG. Desktop requires a flushed positive resource receipt in addition to a normal process exit. This applies before readiness too. A dead Host with unknown resources offers an honest App exit and retains Home. Failed relocated packaging smoke retains its private Home and cannot report success from a raw process exit.
