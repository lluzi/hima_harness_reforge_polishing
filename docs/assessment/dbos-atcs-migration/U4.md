## 实现与职责

`task-effects.ts` 为确定命令、程序、Workshop、Team 和驻场工程提供同一输入验证、
原身份核对、成果保留、资源收束与结果提交协议。它不选择下一节点。
DBOS workflow 直接调用 datasource 事务；外部 I/O 单独进入 Step，实际发送前查询当前
PG 控制和 Site Permit。已准入而回执未知的效果只核对原任务，不重发。
具体事务、Job 和驻场工程说明见 [U4-core](U4-core.md)。

Workshop 复用原生会话、受限写入工具、程序 Job 和独立 Reader。Code 以真实工具调用 ID
及 PG outbox 顺序保留；重复调用不能覆盖较新代码，运行中的程序持有代码与资源边界。
Team 复用原生子会话和同会话跟进；输入读取、模型请求、工具和角色上下文从 PG grant
恢复。Operator 通过普通 Host 工具入口操作已冻结的交互绑定，关闭须证明实际进程和资源
已经收束。没有增加第二个 Agent Loop 或调度器。

Pack 作者明确声明业务输入和 `TASK_OUTPUT`，Host 负责平台身份与产物 hash。
真实模型作者检查实际生成并执行两个 Python 生产者，验证结构化交接和 Goal false；
这项检查不是 App Run 或 ATCS 验收。
