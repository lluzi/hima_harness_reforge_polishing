## Product corrections implemented after the findings

- Foundry/custom synthesis now bind the Campaign's current `periodNs` instead of merely logging it.
- Both synthesis arms apply the same 50% clock uncertainty and now explicitly group and report
  reg2reg paths; both emitted route SDCs apply 25%. A global I/O violation cannot satisfy the pressure gate.
- The default floorplan utilization is 0.25. The foundry arm freezes its core box and placed IO
  plan; the generated arm must reuse the same core and canonical pin identity.
- A `custom-cell-adopted` Judge now sits before PNR. Zero synthesis adoption cannot spend route
  resources or reach a physical-success claim.
- The Path 1 parser accepts both observed Innovus 23.14 slack markers while preserving exact WNS
  equality and analysis-view checks.

These corrections enforce the requested comparison discipline. They do not make the fixed mining
algorithms competitive and therefore do not satisfy PLS-35.

## Remaining method gap

The current AI writes selection programs over candidates produced by six fixed miners. The off-target
screen cannot decide competitiveness under the corrected reg2reg constraint. After the AES/reg2reg
baseline is established, the next Pack upgrade must use the existing Workshop mechanism for a Research Agent to
write the discovery algorithm after reading the current netlist, timing, Liberty, occurrences and
prior adoption feedback. Mechanical generation/layout/prediction can cover a broad candidate pool;
the limited DC screen admits only candidates with actual synthesis adoption, and PNR runs only after
that gate. This is a Pack method change inside the existing Harness/Fabric architecture.

PLS-35 remains open until one `aes_cipher_top` Campaign proves explicit reg2reg pressure, reaches a clean matched route, final database
adoption and strictly higher Fmax, followed by the existing offline auditor, candidate packaging,
Catsights review and user signoff.
