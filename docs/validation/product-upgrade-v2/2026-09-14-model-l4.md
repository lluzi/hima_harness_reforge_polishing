# Product Upgrade v2 model L4

Status: PASS after correcting the retired model id. DeepSeek's official API currently advertises
`deepseek-flash`; a direct one-token probe returned HTTP 200, and the Hima L4 task completed through
that route. The product presents it as DeepSeek-V4.1-Flash.

## Intended check

One isolated Hima Home was prepared to exercise the user path in a single model turn:

1. answer product and Pack questions from the injected HimaGuide context;
2. search and read one imported offline PDF excerpt through `hima_knowledge`;
3. write and execute a generic candidate selector against held-out input; and
4. attach the selected knowledge excerpt to the current owner node and attempt.

The successful request used `deepseek-official/deepseek-flash`. The credential came from an existing
local trial profile and was neither printed nor copied into this repository.

## Retired-id attempt

Three setup attempts stopped before any model request because the macOS knowledge path check did
not treat `/var` and `/private/var` as the same canonical filesystem location. Each failure was
converted into a narrow path fix and a local five-case regression check. Commits `12f557e`,
`da56915` and `5b60ead` contain those fixes.

After those local gates passed, the actual model request remained open for 240 seconds. Session
inspection at the deadline found zero assistant messages, zero tool calls and zero tool results.
The test was terminated by its own deadline. No response was inferred and the attempt was not
counted as a pass.

## Corrected-model result

After the user identified the renamed model, the official `/models` response was checked with the
existing local credential. It listed `deepseek-flash` and `deepseek-v4-pro`; a minimal
`deepseek-flash` completion returned HTTP 200 and `OK`. The Hima profile now overrides dsh-base
0.1.5's retired default in its existing patch layer and gives the replay adapter the same route.

The final L4 completed in 20.364 seconds. The real Agent:

- answered HimaHarness, Campaign, Run, Site, Fabric and Pack identity from supplied product context;
- used `hima_knowledge search` followed by `hima_knowledge read`, with no glob, grep, web or source
  discovery;
- attached page 1 of the PDF as Campaign knowledge record
  `run-219ebfd3-d0b4-4384-af89-464f6df3fa52#000002`, bound to node `synthesize`, generation 1,
  attempt 1;
- wrote a 5,047-byte generic Python selector without either test candidate id; and
- selected `candidate_beta` from the first input and `new_high` after the candidate ids and evidence
  values changed.

The generated algorithm and machine-readable evidence are retained under
`model-l4-v4.1-flash/`. Selector SHA-256 is
`6b65898ecb1a7763e77044a44cbd53f03cf1300b6b914e4a89b6ce708ed09ced`.
