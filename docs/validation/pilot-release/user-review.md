# PLS-26 独立 Agent 代操作审阅

授权：用户明确允许由指定独立 Agent 以工程师视角操作、录屏、审阅并按实际结果决定是否关单；用户稍后 Review 和实际试用。本记录不得称为真人认可或客户效果证明。

## 操作条件

候选应用、一次性 Site/凭据/输入准备和真实 pilot 资产由实施者提供。审阅 Agent 不参与候选实现，不通过源码、测试夹具或后台改状态完成用户操作。桌面控制使用实际应用界面；如遇阻塞，记录后交实施者修复，不自行悄悄补状态。

关闭 App 后不要再调用会自动重新启动该 App 的状态读取入口；通过应用清单或进程退出确认关闭，再由受控的 Catsights 启动入口重开。

Catsights 必须在线，所有测试窗口和录像限定在该副屏。启动不占用主屏；不操作用户其他应用、会话或作业。录像保存在本地交付位置，避免将私有研究、账号或客户资料上传到公开仓库。界面中无需展示密钥。

## 使用任务

- 从准备好的桌面理解可用 Pack、Site、输入和预算；说明哪些是一次性准备、哪些属于每日操作。
- 通过同一对话完成一个小型 Coding 请求，在产品中找到生成的代码或文件，并检查结果。此步骤使用真实模型，范围局限于试用工作目录。
- 发起一次有界研究或知识复用，要求 Agent 在开始昂贵工具前暂停、解释节点和下一步；从运行状态确认暂停/继续或取消的实际结果。不得为了界面检查重跑完整 P&R。
- 阅读完整 pilot 的结论、参考/实际路径、执行代码、原始证据及归档，独立解释执行成功、目标达成、负结果与未验证内容的区别。指出看不懂或无法取得的材料。
- 关闭并重新打开候选后，确认历史仍能读回，未凭空启动新的研究；记录冷启动或恢复卡点。

## 审阅交付

记录候选 commit/Pack/build 身份、实际操作、问题、截图时间点与录像文件/hash；逐项给出通过、失败或未验证。对阻断日常使用或可能误导结论的问题要求修复并重验相关路径。没有实际操作/录像时不能判为通过。

审阅 Agent 给出独立结论及是否建议关单；实施者复核证据真实性后更新 Issues。用户对录像的 Review 和后续实际试用反馈保持独立，不因 Agent 通过而提前标为完成。
