# Offline PDF knowledge POC — unpdf 1.8.1

Date: 2026-09-14

Decision: pass the bounded text-PDF gate and use `unpdf` as the built-in parser behind Hima's
existing knowledge/Ledger seams. This does not claim OCR, image or complex-table support.

## Input and boundary

- Public EDA document: YosysHQ Docs, generated 2026-03-31, downloaded from
  `https://yosyshq.readthedocs.io/_/downloads/en/latest/pdf/`.
- Input SHA-256: `e44df98252aa3ed4963103867e7bceff2cc36a971af7bf9fbab83622c7e46a03`.
- Input bytes: 125,106; pages: 11.
- POC directory: isolated `/tmp`; no Hima home, Site, customer document, model or EDA tool was used.
- Parser: `unpdf@1.8.1`, MIT, bundling Mozilla PDF.js; npm unpacked size reported as 2,141,399 bytes.

## Gold results

All four exact source questions resolved to one expected page in extracted page text:

| Question | Expected and observed PDF page |
| --- | ---: |
| Which environment variable points to the licence file? | 5 |
| How many cores or hardware threads does one node licence cover? | 7 |
| Does the suite transmit node-licence usage data? | 7 |
| What adjustments are required for floating licences in Docker? | 8 |

The parser returned 7,066 text characters. One measured run took 236 ms inside Node 24; process RSS
grew by about 37 MiB and `/usr/bin/time` reported 88,408,064 bytes maximum RSS. The results establish
page-preserving text extraction and exact-source citation on this public text PDF.

## Product consequence

Hima stores the original identified document, creates bounded page-linked excerpts, searches those
excerpts locally, then records only the excerpt actually returned to a Campaign Agent as a
`KnowledgeRecord`. The index is derived and rebuildable. Current documents live outside the Pack,
remain scoped, survive restart and can be explicitly cleared; importing one does not change a Pack
digest.

Scanned PDFs, diagrams, formulas and complex tables remain an explicit unsupported/partially parsed
case for this trial. The product must report missing extracted text instead of inventing an answer.
