HimaHarness 使用评估手册

使用手册 · 评估记录表 · 管理员交接 · 评分 CSV

从零理解产品，完成第一次试用，并给出有依据的评价。

版本：手册 1.0 · 对应应用 v0.2.0-trial.1 / AES DTCO Pack 5 · 编写日期：2026-09-14。

本手册面向没有项目背景的评估者。一般软件试用不要求芯片设计经验；真实芯片研究需要 CAD/EDA 环境负责人协助。这里的“评估”是判断产品是否适合你，不是代替芯片签核。预计时间均为活动安排建议，不是性能承诺。

先做什么：阅读第 1-5 章，完成第 7 章的本地编码练习。拿到管理员提供的历史资产后，再做第 8-11 章。真实 EDA 试验放在最后，由负责人确认。

配套材料：可填写的《评估记录表》、评分 CSV、管理员交接清单。PDF 适合阅读与分发；HTML 和 Markdown 适合复制练习提示词。界面区域以示意图说明，不包含客户截图或数据。

01 先选一条适合自己的试用路线

第一次试用不需要把所有功能都跑一遍。先判断自己拿到了什么环境，再选择路线。

路线谁适合需要什么建议用时完成后能评价什么
A：了解与编码任何评估者可启动的 App、可用模型凭据、空白测试工作区30-45 分钟对话、文件创建、代码执行、解释是否可信
B：研究阅读与控制已拿到演示环境的人A 的条件，加已归档 Run、Pack、已配置 Site、交接卡45-60 分钟图、状态、证据、暂停/取消、知识引用
C：真实研究工程师与环境负责人共同进行合法可用的设计/库/EDA/模型、Site 准入、预算单独预约当前设计与环境下的研究闭环和方法价值

路线 A 不需要 EDA。路线 B 不重复整轮物理实现，但创建 Run、准备工作区和归档可能访问 Site 并产生文件 I/O。路线 C 才会消耗真实 EDA 资源和许可证。路线 A/B 仍可能产生模型 API 费用；活动时长和 Run 时限都不是金额上限，账号费用边界由负责人确认。

开始前填写交接卡的应用版本、启动方式、测试工作区、联系人及允许范围。空白字段不是“默认已准备好”。缺少 Site 或历史资产时，先完成路线 A；将路线 B/C 标为“未评估”，不要给它们随意打低分。

第一次的完成标准：你能解释产品在做什么，自己完成一次小型任务，找到实际结果，并知道哪些内容还没被验证。

02 这是一款什么产品

HimaHarness 是面向复杂工程研究的 AI 工作台。它把对话、代码、业务运行状态、工具结果和研究证据放在同一个工作界面中。

一个典型过程是：工程师提出问题和限制；Pack 提供研究方法的骨架；同一个对话 AI 读取数据、形成策略、编写必要代码并组织试验；工具执行计算或测量；系统记录过程和依据；工程师检查结果，决定下一步。

它的产品目标是让一个有经验的工程师组织过去需要跨领域协作才能开展的探索。这个目标还不是“已经证明可以替代一个团队”的宣传结论。评估应检查具体任务中的能力和局限。

常见工具主要提供什么HimaHarness 增加的关注点
普通聊天助手解释、建议和文本建议能否进入实际代码、工具和反馈闭环
编码助手编写、修改和运行代码代码怎样对应业务节点、输入与研究结论
固定自动化脚本按预设流程执行运行中怎样调整策略、追加研究、保留证据
单点 EDA 工具某一设计或验证环节多个工具与研究判断怎样协同工作

可以先把它用于普通编码。进入研究任务后，你要评估的重点是：AI 的工作是否建立在实际数据上，行动是否受控，结论是否能被检查，失败能否为下一次研究提供输入。

03 不懂芯片设计，也能理解示例在研究什么

芯片设计会反复权衡速度、功耗、面积和实现难度。EDA 是辅助设计和验证芯片的软件工具集合。HimaHarness 自身不替代这些工具。

词语初学者解释在试用中怎么看
RTL描述数字电路行为的代码研究输入的一部分
Cell / 标准单元构成电路的基础积木，例如逻辑门定制 Cell 是为特定机会制作的新积木
综合将 RTL 转成由单元组成的电路网络产生网表、面积和时序等报告
布局布线 / PNR放置单元并连接导线更接近实际物理实现，代价也更高
PPA性能、功耗、面积的合称不能用一个数代表所有优劣
Fmax在规定条件下能可靠工作的最高频率需要满足时序等条件，不能仅从目标推导
DTCO联合考虑设计与工艺/器件等因素的优化强调跨环节探索和系统性权衡
签核 / signoff达到规定交付条件的正式验证本轮试用不构成芯片签核

本版的代表案例研究 AES 电路中的定制 Cell 机会：寻找候选、选择值得尝试的结构、生成单元、做库处理、比较基准方案与定制方案的综合和物理结果。

可以把它理解为改造积木来改善一座建筑。积木能制造出来、模型能接受它、建筑能搭起来、建筑最终满足目标，是几件不同的事。对应地，“脚本成功”“工具结束”“流程完成”和“设计目标达成”必须分开判断。

04 六个概念：先知道谁负责什么

概念作用容易混淆的地方
Workspace 工作区本地对话、编码和文件操作的项目目录不一定是远端 EDA 的执行目录
Agent 对话 AI与你交流，并请求执行业务节点、代码和工具它的文字解释不自动成为已验证事实
Pack 方法包目标、参数、参考路线、工具/数据约定和知识安装方法包不等于已有私有数据和许可证
Site 执行站点指定在哪儿运行、用什么资源和权限可能是本机，也可能是 SSH 连接的服务器
Run / Campaign一次有身份、输入、目标和预算的研究记录新对话不等于新 Run；已有 Run 也不等于正在运行
Fabric 执行基础设施检查依赖、权限和预算，跟踪 Job，记录状态主产品路径的业务推进由对话 Agent 请求

Job 是 Fabric 记录的一次工具作业。普通编码中的原生 Bash 命令与 Hima 实验 Job 不是同一个计数口径。例如一次本地短等待可以出现在对话工具日志里，但 Hima Job 数仍为零。

Home 是应用保存会话、Run、Pack 和相关状态的数据位置。它不是当前编辑的工作区。更换 Home 可能让历史看起来“消失”；不要因此删除旧目录或反复创建 Run。

知识资产包括技术报告、算法代码、数据身份、结果、局限和后续建议。它们帮助下一次研究提出更好的问题。历史经验不能被冒充为新试验的测量结果。

另外几个常见词：Goal 是固定研究目标，Strategy 是本次尝试的策略；Reader 把工具原始输出读成结构化事实；Judge 按声明规则判定 PASS、FAIL 或 UNDETERMINED（尚不能判断）；Workshop 是允许 Agent 编写并执行研究代码的节点工作区。文档提到 HimaGuide 时，指对话和方法引导能力，本手册不假设存在一个同名独立按钮。

05 当前试用版的能力与边界

本手册固定对应 v0.2.0-trial.1。应用发行源提交为 207d22f，AES DTCO Pack 版本为 5。版本变化后，应重新核对按钮、参数和支持范围。[S01][S02]

当前有证据的能力尚不能由此推出的结论
正常对话、文件创建、实际 Python 执行和代码查看所有编程语言、环境和任务都已验证
一条真实 DTCO reference path 完成 51 个节点和 45 个 Job所有候选策略都正确，或已获得性能收益
对话 Agent 控制节点，记录状态、代码和证据任意节点都能无条件增加任意工具
ready 探索点的增长修复经独立真实模型补验原 DTCO Run 中被拒绝的支路已被事后执行
历史资产读取、受控分析、取消和重启读回已证明长期知识积累的商业回报

必须保留的事实：该真实 DTCO Run 形成未达标结果；完整约束检查有两类失败。前三路选择程序误解了数据字段结构而返回空选择，不能解释为这些路线没有优化机会。原 Campaign 的附加支路被拒绝，控制修复是在独立 L4 中补验的。

发布前的操作验收由获授权的独立 Agent 完成。真人的使用感受和研究价值判断仍应由你给出。

发行包支持本轮验证过的 macOS Apple Silicon 路径，自带 Node 24，采用 ad-hoc 签名，尚未公证。它不包含私有 Site/PDK 输入、模型密钥、EDA 许可证或客户研究历史。

06 安装、启动与第一次进入

本机桌面不等于模型和数据都在本机。本版试用使用配置的 DeepSeek API；对话、所选文件及工具返回内容可能进入模型服务。先使用合成或获准的试用数据，由负责人确认数据流和服务端政策；不要假定这是纯离线产品。

已由项目组准备好的本机

使用交接卡中指定的启动器。项目组本机有一个 Start HimaHarness.command，它读取已有凭据并连接保留历史的 Home。它是本机专用入口，不是通用下载包中的安装器；不要直接转发给另一台机器使用。保留它与应用、数据目录之间的关系。

启动后，在侧栏找到提供的工作区。出现 Choose workspace 时，选择交接卡中的测试目录。如果看到 Internal Testing Notice，阅读说明再继续。成功标志是进入对话输入区，能看到模型选择和工作区；欢迎页出现本身还不证明 API 可用。

只有通用下载包的新机器

1. 从版本下载页取得 ZIP 和 SHA256SUMS.txt；环境负责人按第 16 章核对文件。

2. 解压 .app，由负责人一次性设置模型凭据和隔离的数据目录。日常评估者无需安装 pnpm 或编译源码。

3. 按组织批准的方式处理 macOS 的应用安全提示。本包未公证；不要自行关闭系统安全保护来绕过提示。

4. 打开后选择一个专门的空测试目录。用第 7 章确认模型能实际响应并执行任务。

看到空工作区或没有历史 Run，不一定是故障。公开包没有私有历史资产。只有管理员交付了 Pack、Site、数据及记录，路线 B/C 才具备条件。没有确认过的模型密钥配置界面，不应靠猜测寻找；本版明确支持向启动进程提供凭据，见管理员章节。

07 第一个练习：普通对话与编码

目的：不用芯片资料或 EDA，验证对话、文件生成、执行、查看和解释。只在一个空的测试工作区操作。建议给自己 10-15 分钟；这不是应用的执行预算。

在新会话中粘贴下面的提示词，发送前检查文件名和符号是否完整：

请在当前测试工作区创建并运行 timing_demo.py，仅使用 Python 标准库。
使用这些合成数据：
A: period_ns=1.00, setup_wns_ns=0.05
B: period_ns=0.80, setup_wns_ns=-0.04
C: period_ns=1.20, setup_wns_ns=0.00
规则：setup_wns_ns >= 0 为 PASS，否则为 FAIL。
计算每行 setup_wns_ns / period_ns，比值保留四位小数，按比值从小到大排序。
展示实际文件、实际运行命令和输出，并解释一项局限。
不得访问 Site、运行 EDA、创建 Campaign 或安装新依赖。
独立预期应看到的结果
APASS，比值 0.0500
BFAIL，比值 -0.0500
CPASS，比值 0.0000
排序B、C、A

点击回复中的文件入口或 Files & code，检查代码确实存在。再检查工具记录中有实际命令及输出，而不只是“我已经运行”的一句话。出现 python3 不存在时记录环境缺口，请管理员处理；App 自带 Node 24 不等于自带 Python 或所有开发工具。

最后追问：“如果按绝对 slack 而不是比值排序，结果说明了什么？这些合成数据能证明真实芯片性能吗？”合格回答应说明样本与指标的限制。数值正确、代码实际执行、局限讲清三项分别记录。

界面区域示意，非实测截图。

界面随窗口尺寸可能收起侧栏。寻找功能名称，不必追求与示意图像素一致。

区域常见入口你在这里做什么
① 工作区与会话侧栏Workspaces / New Session选择本地项目、找到过去的对话
② 对话区域Chat / 工具调用 / 输入框提问题、给约束、查看 Agent 的行动与回答
③ 研究状态区域Live Run选择一个 Run，查看状态、目标、预算和执行轨迹
④ 结果与材料Experiments / Evidence / Report读实验、证据与技术报告

打开 Live Run 后，在 VIEWED RUN 的下拉框选择管理员给你的 Run。面板打开但仍显示“Select a run on this host”时，是尚未选择记录，不是该 Run 没有结果。

旧对话中的 Run 卡片可能是当时的快照。需要当前状态时，用 Live Run 的刷新入口，或让 Agent 读取最新上下文。不要把旧消息中的“running”当成当前仍在执行。

会话与 Run 的关系很重要：一个对话可关联研究操作；Run 保留其执行 owner。仅在右侧查看某个 Run，不保证当前左侧对话就是它的 owner。控制被拒绝时，应进入对应的原会话或按产品允许的交接流程处理，而不是换个会话继续强行尝试。

09 第二个练习：阅读一份已有研究

前提：管理员已提供可读的历史 Run 和必要材料。不要为阅读报告点击 New run。建议用 15 分钟回答下面六个问题。

1. 问题是什么？ 找到设计、Pack 版本、Site、Goal。Goal 是要达到的目标，不是已经取得的结果。

2. 实际上做了什么？ 查看 reference path 与记录的执行轨迹。记录完成节点、未走分支、失败与重试，区分计划和已执行行为。

3. AI 做了什么？ 找到至少一份算法或脚本，查看输入、代码身份及相应 Job；指出其中一次调整的依据。

4. 结果来自哪里？ 从 Report / Evidence 找到一个关键判断对应的观测、原始材料或读取记录。仅有聊天总结还不够。

5. 为什么结束？ 查看最终状态、停止原因和预算。工作流结束可以是未达标结果。

6. 什么不能推出？ 找到局限、未测量内容和下一次试验建议；至少写下一条你认为不能做的外推。

如果使用本轮交付的正式示例，应识别：51 个参考节点已完成，但设计目标没有完整达到；三路空选择有算法字段缺陷；原支路拒绝仍在历史中。不要把“51/51 完成”翻译成“设计成功”。[S02][S03]

然后用自己的话写出三句话：本次研究的问题、最有依据的结论、下一步最值得验证的问题。请把看不懂或找不到的地方记录为具体卡点，而不是泛泛地评价“界面复杂”。

10 状态、预算与停止：哪些信号才算数

状态或动作正确理解接下来怎么检查
runningRun 仍开放，可能执行或等待 Agent/资源当前节点、在途 Job、最后更新时间
paused / Pause Run阻止范围内的新业务动作已有 Job 是否仍在运行；暂停不是立即杀进程
waiting / blocked存在明确阻塞，可能需要人处理原因、已尝试动作、可用的合法下一步
Continue Run在允许条件下解除暂停或继续不会自动清除所有失败，也不会重置预算
Stop Run / cancel请求终止并等待实际结清Run 状态、stop 确认和 Job 实际状态
ended-goal-met声明的规则支持本次达到目标仍须核对规则、范围和证据
ended-budget-exhausted某类预算或代数上限触发结束不一定用完了墙上时钟时间
cancelledRun 已按取消请求结清不等于设计试验给出了负结论

暂停时 Run 仍可能显示 running；应核对暂停范围与实际 Job，不要求状态文字一定变成 paused。

本版正式 Pack 的总尝试上限为 120，并预留 60 秒收尾时间。具体 Run 还可限制总时间、代数、重试、并发和许可证。预算是多条边界，任何一条都可能先到。[S05]

预算到期会停止 Campaign 作业和新的研究分析写入；对话仍可回答。结束后的聊天不能自动算作该 Campaign 预算内的新成果。关闭窗口也不能被当成可靠的暂停按钮；中断后应先核对实际 Job 状态。

“请求已接受”“不再启动新工作”“在途 Job 已停止”“归档已完成”是四种不同的状态。评估时要求逐项说明，避免用一个“已停止”替代全部事实。

11 第三个练习：引用历史，暂停并取消

这项练习使用已准备好的 Site，但不运行实验 Job。需要管理员先填好本节所有占位符，确认允许新的工作区和归档文件 I/O。不要把 <...> 原样发送，也不要凭记忆编造路径或 hash。

必须有：Pack/Site、相同 Goal、来源 Run ID、该 Run 归档的本地 manifest.json 与 experience.md 精确路径、manifest SHA-256。site: 开头的材料地址不是普通本地文件路径；让管理员提供合适的读取入口。

begin、work 是 Agent 请求的节点动作，不是要求你寻找这两个按钮。你也不需要手工猜测 epoch/revision 等内部控制编号。

在一个新的会话发送：

总时限 5 分钟、1 代，重试参数 retries=2。任何节点开始、work 或 Job 提交之前，
先在 Run 范围暂停，读取当前状态并确认没有已接纳的节点执行或 Job。
然后用普通 read 工具读取：
<MANIFEST_LOCAL_PATH>
<EXPERIENCE_MD_LOCAL_PATH>
在入口节点记录分析：claims=[]，引用来源 <SOURCE_RUN_ID> 和
manifest SHA-256 <MANIFEST_SHA256>，写明局限与下一次验证建议。
不要提出新的数值测量断言。最后取消这个同一个 Run，并核对实际结清。
不得开始实验节点、运行 EDA、安装依赖或额外新建 Run。

对于已交付 AES Pack 5，入口节点为 probe；交接人员可使用 Goal target_period_ns=0.5，策略 periodNs=0.5, algorithmRevision=1, floorplanUtilization=0.5。只有确认了该 Pack/Site/输入才使用这些值。

合格证据：暂停发生在实验前；两份来源材料确实被读取；分析引用正确来源；同一个 Run 最终取消；实验 Job 与已接纳执行仍为零；归档可读。取消可能写下一条 probe cancelled 的管理记录，它不代表执行过实验。

工具拒绝错误参数时，允许 Agent 根据明确提示修正，但应记录失败、重试及最后结果。若开始了未经允许的实验，先停止并记录，不通过改历史或追加 Run 来掩盖。

12 怎样与 Agent 合作和介入

给 Agent 的指令应包含对象、目的、边界和可检查的结束条件。自然语言可以提出任务；控制是否生效仍看实际记录。

你的意图可直接改写使用的提示词
了解现状只读取 Run 的最新上下文。说明当前节点、在途 Job、已知失败和可用动作。先不要推进。
暂停暂停这个 Run 的新业务动作；分别报告请求是否接受、哪些 Job 仍在运行、是否实际结清。
检查结果查看节点的输出、读取记录和规则依据。区分事实、推断与未知，不用失败产物补结论。
调整算法先说明将改哪些输入/代码、影响哪些下游、哪些结果仍可复用以及预算，再提交合法修订。
附加研究在 Pack 声明的探索位置提出附加支路，说明输入、结束条件、影响范围与返回位置；保留参考图。
取消取消此 Run，等待实际确认；列出未结清 Job 或未交付材料。不要只停止聊天。

参考图提供基础路线，AI 不能任意删改它。附加节点使用 Pack 与当前架构允许的能力；遇到“不支持”“不在声明位置”或权限拒绝，应解释限制，不能通过普通 Bash 绕开业务检查。

回溯与重新执行也不是删除历史。合理行为是保留原尝试，复用仍有效结果，重跑受影响下游。已结束 Run 不应被当成可以随意改写的在途状态；需要新研究时，明确创建新 Run 并引用旧资产。

如果你不知道一个操作会影响什么，先要求“只给检查与影响说明”。这既降低试用成本，也便于你判断 Agent 是否理解任务。

13 阅读结果：成功、负结果、故障和未知

判断顺序应是：材料是否完整可靠，条件是否可比，规则是否通过，结论是否超出了证据。

结果类型示例合理的结论
工具执行成功退出码为 0，产生了可读取报告该操作完成；不自动等于设计达标
有证据的未达标结果有完整比较，规则显示时序仍不满足该条件下尚未达到目标，并记录原因和下一步
执行故障工具崩溃、缺许可证、报告格式不能读先处理执行问题；不推出策略好坏
覆盖不足预算只允许少量试验，部分路线未有效探索结论只覆盖实际完成的范围
未知缺数据、hash 不符或条件不能匹配明确不知道，补证据后再判断

一个纯教学例子，非本轮实测数值：目标周期为 1 ns，基准方案的 setup WNS 为 -0.10 ns，候选为 -0.06 ns。差值改善了 0.04 ns，但两者仍有负裕量，不能说已经稳定运行在 1 GHz，也不能把差值直接称为 Fmax 提升。

WNS 是最差时序裕量；负值通常说明相应时序要求仍不满足。还要看分析模式、路径范围和约束。full_constraint_failures 统计失败条件的类别数量，与 DRC 错误条数不是一回事。

预测表征、工具测量、推算和用户设置的目标不能互换。库能通过 Library Compiler 不意味着已经完成 SPICE 校准或芯片签核。对比至少核对设计、输入、约束、库、工具、分析条件和测量定义。

14 怎样找到、保留和使用知识资产

在选定 Run 的研究面板中，打开 Report / Evidence，查看 KNOWLEDGE ARCHIVED IN THIS PACK、Pack & assets 等入口。名称可能因面板状态稍有变化；Verify archived materials 用来核验材料，而不是重新做一次实验。

典型资产包括 experience.md、experience.json、代码、输入/输出材料及 manifest。方法与运行资产分别保存；固定归档位置为对应 Pack 下的 run-assets/<Run ID>/。实际目录由管理员交接，评估者优先从应用进入。

hash / SHA-256 可以理解为文件的数字指纹。hash 一致支持“这是同一份字节内容”，不证明算法正确、测量可比或结论有价值。还需要版本、环境、适用性和业务判断。

复用历史时至少回答四个问题：来源是哪一条 Run？方法与环境是否相同？哪些内容还能适用？哪些必须重新验证？本版的五分钟练习只验证引用和控制，不能证明跨设计的自动结果复用或长期收益。

分享 Pack 前区分两件事：分享参考方法，还是迁移包含客户结果的整套资产。默认不要把客户数据、专有算法、凭据或 PDK 发到公共仓库。不要通过手动修改已归档文件来“修正报告”；新的认识应有新的记录，方法升级形成新版本。

备份/迁移由管理员执行：先停止对应 Host 和相关工作，保留 Home、工作区、Pack 资产及 Site 信息的适用关系。单独复制 .app 不会带走历史；单独复制 Ledger 也不能假定带齐材料和 owner 会话。

中断后的最小恢复顺序

先恢复必要连接并使用原来的启动方式/Home；找到原 Run；让 Agent 只核对当前状态、在途 Job 和已有产物；依据明确的恢复或重跑选项继续。暂时读不到 Site 时应保留“未知”，不能认定 Job 已死，也不能直接重复提交。已结束的记录继续保留，新的研究另建 Run。

15 什么时候才进入真实 EDA 试用

完成前面的阅读和控制练习之后，由研究负责人明确一个小而可判定的问题。第一次不要使用“尽可能优化，直到满意”这样没有边界的任务。

开始前确认负责人需要给出的内容
研究问题要改变什么，如何判定有效，哪些约束不能牺牲
输入与方法设计、库、Pack 版本与 digest、有效 Site、输入身份
资源授权SSH/容器/工具可用，许可证和并发额度已落实
预算总时限、代数、重试、尝试上限、并发及结束条件
对照与解释双臂条件怎样匹配，预测/测量怎样区分
恢复与保留如何停止，谁处理阻塞，产物存在哪里

本轮已验证的研究使用了一代、90 分钟总时限、重试参数 retries=2 和一次并行 Job。它是特定 pilot 的设置，不是所有用户的推荐预算。管理员应解释参数后填写交接卡；普通评估者不盲目照搬。

AES Pack 5 的 periodNs 是初始 probe 策略；后续双臂物理流程还使用 Site 的 legacy.CLOCK_NS。不能以为只改一个界面字段就自动改变所有测量条件。floorplanUtilization 是初始利用率，不是最终密度；其允许范围为 0.2-0.8，默认 0.5。[S05][S06]

真实运行中记录里程碑和卡点，不要为了截图重开整轮 EDA。出现未知或故障时，回到最低成本的检查层。结束后交付的不只是一个数字，还应包括程序、数据身份、实际执行、局限和下一次可检验的问题。

16 管理员：客户端交付与凭据配置

本章由负责准备环境的人执行。普通评估者只接收准备好的启动入口和交接卡。

1. 核对机器为本轮支持的 Apple Silicon Mac；下载固定版本 ZIP、校验文件和应用清单。ZIP 大小为 271,694,896 字节，约 259 MiB。[S01]

2. 将 ZIP 与 SHA256SUMS.txt 放在同一目录。若运行 shasum -a 256 -c SHA256SUMS.txt，还需同时下载其中列出的 trial-manifest.json。

3. 解压并准备独立数据位置与足够的存储空间；工作区和 EDA 产物另行规划。Python、Git 和项目依赖不保证随 App 提供，须确认本次练习所需工具。不要误用正在开发或他人正在运行的 Home。

4. 通过获准的凭据管理方式，将 DEEPSEEK_API_KEY 提供给应用进程。不要发到聊天、截图或评估表里。设置变量不会自动证明凭据有效，应以一次小任务实际确认。

下面是管理员启动示例，要求密钥已进入当前环境；<APP_PATH> 必须替换为实际 .app 位置。它不是通用安装器，不会安装 Site/EDA。

# 在已通过授权方式加载凭据的 shell 中执行
: "${DEEPSEEK_API_KEY:?请先配置模型凭据}"
trial_dir="$HOME/Library/Application Support/HimaHarness-Evaluation"
mkdir -p "$trial_dir/workspace"
DSH_HOME="$trial_dir/dsh" \
DSH_AGENTS_HOME="$trial_dir/agents" \
HIMA_USER_DATA="$trial_dir/desktop" \
HIMA_WORKSPACE="$trial_dir/workspace" \
DSH_TELEMETRY_DISABLED=1 \
"<APP_PATH>/Contents/MacOS/HimaHarness"

请交付可重复使用、不会打印密钥的启动方式。仅在 Terminal 中设置变量，并不等于以后从 Finder 打开的 App 自动继承它。本版打包入口在未指定 DSH_HOME 时使用应用数据目录中的 trial-dsh；切换启动方式/Home 前必须记录清楚。[S07]

17 管理员：Site 与真实研究准备

公开包包含方法，不包含完整客户环境。本版已经验证的是明确的试点 Site，不能承诺任意机器解压即可跑 DTCO。仓库里的历史 Site 示例也不一定等于最后实际使用的配置，不要直接复制其中的旧路径或仅含一种许可证的容量声明。

交接类别必须准备与检查的内容
Site 定义本地/SSH 类型、连接目标、可写 workspaceRoot、flowRoot、design、Permit
资源和范围CPU、内存、并发 Job、DC/LC/Innovus 许可证、允许读写路径及 wrapper
设计与库RTL/top、foundry DB/Liberty、LEF/技术 LEF、QRC、GDS/映射及相关模板
单元生成与布局bool2cmos、布局技术/规则/供电轨、容器运行时与挂载、必要辅助工具
预测表征表征辅助程序、时序/功耗/面积模型及其适用性说明
流程参数共享时钟、单元分配、候选限制、每阶段超时、验证上限和分析条件

Pack 5 使用私有 inputs.json 绑定这些资源。evidenceClass 的真实运行值为 site-run；synthetic-fixture 只能用于明确标注的本地测试，不能改个标签冒充真实工具结果。

先做文件/版本/权限检查，再做最小模型与工具检查，最后才开完整研究。一次 Site 准备不代表所有后续输入都自动有效；绑定、工具或库变化后重新验证适用范围。LC 的某个版本能启动，也不等于它已正确接受当前生成库。

完整字段分组、权威文件与交接表见配套《管理员交接参考》。应由 CAD/EDA 负责人填写真实值；任何缺失值都不要用演示路径、假文件或未经验证的默认值替代。

19 怎样评分，避免只凭印象

使用配套评估表。每个分数都应带一条观察证据、使用版本和环境；未准备/未操作的项目填 N/A，不计入平均值。下面的时间是评估安排，不是性能指标。

维度你要回答的问题
理解成本我能否在 15 分钟内解释 Agent、Pack、Site、Run 和 Job？
上手与配置交接完成后，能否独立启动、选工作区并完成小任务？
编码闭环我能否找到实际生成的文件、执行命令和正确输出？
状态与介入我能否知道正在做什么，并验证暂停/取消的效果？
证据与诚实结论是否有来源，错误/未知是否被保留？
知识可用性我能否取到报告和算法，并在新问题中正确引用？
研究贡献AI 的策略/代码是否针对实际数据，反馈是否影响下一步？
日常使用价值哪个过去做不了或成本过高的工作，现在有了可行路径？

只做路线 A 不能据此评价真实 DTCO 效果；阅读旧报告和亲自执行研究也要分别标注。

统一尺度：0＝已尝试但无法完成或会误导；1＝必须由开发者代操作；2＝能在较多指导下完成；3＝能独立完成且证据清楚；4＝能重复完成、主动识别限制并支撑自己的任务。N/A＝没有评估，写明原因。

单独记录阻断项：错误的成功声明、未经允许的昂贵执行、无法确认停止、历史/证据丢失、未获授权的数据分享。出现这些问题时，不应让其他高分将它们平均掉。

最后给出分层建议：可以继续普通编码试用；可以进入受控研究；需要先解决某个阻断；或当前不适合你的任务。不要仅用一个总分代替结论。
