# 保留已交付 polish，接收 Step 4 并在 polishing 完成产品

日期：2026-09-12。用户已明确选择现在整合已提交上游快照，后续 Step 4 在 polishing 完成。本文件是开发计划与验收规格，不是代码已导入、Agent 执行已实现或产品测试已通过的声明。

本轮更新已有父规格 [#1](https://github.com/lluzi/hima_harness_reforge_polishing/issues/1)，保留已关闭任务，新建 PLS-20～26，并调整 PLS-08～19 的后续依赖。当前任务表见 [README](README.md)，来源与文件重叠见 [baseline.json](baseline.json)。本轮对后续开发顺序的规定优先于旧稿中的“等 Step 4 完整交付再开始”与旧模块映射；产品要求仍由根产品定义和已接受 ADR 决定。

## Problem Statement

用户已有一个经过打磨的工程工作区，同时 prototype 已完成模型会话、Pack 自带数据/reader、Workshop 和编写流程的基础代码。继续分别完成正式 Pack、报告和验收，会在界面、执行职责和测试上重复工作。Claude Code 暂停开发后，需要一个可以接续的主线，使已有 polish 不丢失，并在最终产品行为上完成真实 DTCO，而不是等待旧执行方式先跑完再重做。

PLS 已完成的成果包括：低成本测试入口、默认方法修正、输入预检、运行控制、诚实报告，以及原生对话旁的 Run/代码/证据工作区。上游新增基础可以复用，但不能覆盖这些成果。尤其是上游“Fabric 自动 drive，在 Workshop 开一个模型会话”，与用户要求的“同一个对话 Agent 执行业务”不同。

## Solution

先形成保留当前 PLS 行为的可验证集成基线，再实现同一 Agent 的节点执行与控制，补齐正式 Pack 的作者流程和必要声明，逐步带起 AES probe、定制 Cell 挖掘及双臂验证。研究报告、资产归档、回溯与知识复用继续按既有 PLS 要求交付。正式候选上集中执行完整研究与真人使用验收。

唯一集成主线是 polishing；两个参考项目保持只读。所有实现者在 polishing 的任务分支协作，提交立即推送并核对远端 SHA。不会因为切换负责的编码 Agent 而复制第二套开发/验收标准。

### 节点执行与迁移协议

[节点执行补充规格](../polishing-v1/node-intervention.md)定义同一 Agent、Run 控制版本、节点尝试、非阻塞 Job、暂停与恢复。Host 从真实调用上下文确定身份；模型不能自填 owner 取得控制。没有下一项 Agent 业务请求，Fabric 不会自行启动下一业务节点。

本轮将暂停的工程默认细化为：立即停止受影响范围的新业务接纳，当前 Job 可完成并保存事实；明确的立即停止走 Job 终止，并分别确认取消请求和真实退出。它是本轮设计选择，不冒充用户此前逐条确认。真实工具检查点能力必须另有证据。总 time box 在暂停期间继续计时；不通过暂停重置预算。

旧 Run 不批量改写为新模式。保留历史和在途 Job，升级后先追踪与收束，不自动恢复旧 drive；在安全节点边界显式绑定对话所有者后，才允许新模式继续。新字段由已有 Ledger 负责持久化/校验，UI/API/报告统一消费，不新增服务、图引擎或执行主脑。

### Pack 发布与知识资产

上游 `pack-folder.ts` 的方法摘要排除五个 pipeline record 文件，目前未包含运行资产的业务划分。因此在给正式 Pack 引入归档前，PLS-13 必须统一 loader/test digest/release/check/update 的文件范围。不能只让 release 忽略资产，而 Run 身份仍因新增资产变化；也不能以排除整个知识目录来隐藏方法变化。旧格式须保留读取与明确迁移策略。

运行资产仍归入已安装 Pack 的 `run-assets/<runId>/`，上游源码 Pack 与 Golden Flow 不被运行写入。原报告、算法及历史版本可查，缺失内容不得从当前路径补造。对外方法发布由显式方法清单构建，客户资产默认不随包外传。

1. PLS-20 独占整合热点，产出可验证基线。

5. PLS-10～17 的参考图、有效性、预算与资产交付按各自依赖推进；PLS-18 集中做完整双臂研究与第二次知识引用，PLS-26 做真人使用验证。

上游任务的唯一承接关系见 [upstream-disposition.md](upstream-disposition.md)。原项目 Issues 保持只读；本仓库任务记录来源和验收，不替原项目标记完成。

## Testing Decisions

沿用用户已确认的 L0–L5 和现有接口；本次不要求重新确认测试层级。技能的默认“尽量最高接口”在此以仓库 ADR-0005 与用户成本要求为准。纯逻辑用 L1，持久状态/作业/权限用 L2 真实 Host，窗口行为才用 L3，不新增通用测试服务。

| 验证对象 | 最低有效接口与反例 | 升级条件 |
| --- | --- | --- |
| 快照拼装 | L0 新构建/类型/声明/入口归属，L2 导入后的完整 local 与新增合同 | 启动/注册变化做有限 L3；模型接口变更做 L4 模型 |
| 节点控制 | L2 真实 Host+Job：重复/过时请求、伪造完成、暂停竞态、Agent 离线、恢复不自动推进 | L3 同一对话介入；L4 V4 Flash 实际调用与反馈 |
| 参数与 reader | L1 类型/范围/字面值，L2 检查没有启动副作用和合法输入可用 | 新表单一个 L3；真实 wrapper 语义变化最小 L4 Site |
| 作者流程 | L2 安装态+replay+真实文件，缺 reader/知识/错误 release 不能通过 | Skill/工具改变做 L4 模型，模型看不到开发源树 |
| 版本与资产 | L2 真实目录/旧新格式：新增资产不改方法身份，方法改变必改，升级/中断不丢字节 | 启动或错误展示变化才做 L3 |
| 代码与报告 | L2 hash/旧报告/假引用/不同 Run，L3 用户可达的阅读和拒绝 | 研究解释质量用真实小任务，不用固定措辞断言 |
| AES 方法 | L2 九阶段组合；L4 分开的模型和必要真实工具 probe | PLS-18 单一 L5 完整候选；PLS-26 真人独立使用 |

优先复用 `boot-inprocess.ts`、`boot-host.ts`、现有 local Job/stand-in、`driver.ts`。新上游 `moment.test.ts`、`workshop.test.ts`、`pack-readers.test.ts`、`skills.test.ts`、`pipeline-stages.test.ts`、`standin-stages.test.ts` 和 release 相关用例导入时逐项分类，不能仅凭文件名认定无 Electron/SSH 副作用。

日常相关子集 3 分钟、关键 L3 5 分钟仍是目标，不是保证。每轮只构建一次；全组与子集分别计时，记录 Host/窗口启动数、模型调用和 Site 作业投入。桌面串行；进程内环境修改不可盲目并行。完整验证只有新变化、失败或未消除风险才重复。

上游 2026-09-12 的 Workshop 12/12 与 pipeline 38/38 是上游记录的真实模型小场景，外部业务仍有 stand-in，不能作为 polishing 独立通过或真实 AES 研究的证据。尤其 Workshop 样例从面积导出候选数只证明机制，不满足 PLS-09 的算法价值要求。

每次切片保存 commit/构建/Pack/输入/环境身份、命令与退出码、通过/失败/跳过/未跑、材料 hash、覆盖去向与回滚。归档后内容不改写；缺凭据、真人、资源或输入就是未验证/阻塞，不变成 PASS。
