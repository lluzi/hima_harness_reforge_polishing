# HimaHarness Polishing v1：可验证的研究体验、知识资产与经济测试

规格身份：`polishing-v1`。来源：已确认产品访谈、`docs/product-definition.md`、`docs/polishing-backlog.md` 与用户 2026-09-11 的 `/to-spec` 请求。代码基线：`b4ac9d9360ad6da68b5fd2824621ba6edab7408b`，159 个导入文件本轮核对仍与原始 hash 一致。

本规格与任务通过本项目 GitHub Issues 管理；仓库内文档是本次发布的可审阅副本，实时任务状态以对应 Issue 为准。本次只编制规格与任务，不实施产品修改或执行真实研究。

## Problem Statement

资深工程师需要一个能承载复杂 DTCO 研究的产品：将跨领域知识、EDA 工具、算法生成、试验反馈与证据判断组织成一个人可控制的研究闭环，并将失败与成功都沉淀为可复用知识。现有 prototype 已能执行声明的图并展示事实，但不能由此断言 AI 已能自主研究、运行资产已完整交付或整个客户体验已经可靠。

现有开发验证也存在实际成本和可信度问题：新安装后的测试类型检查依赖尚未生成的构建声明；部分 contract 文件在加载时访问真实 SSH；大量非视觉行为由桌面启动承载；默认本地 Pack 的方法在诚实 stand-in 上会不断放宽 period。若用全套桌面和 EDA 反复验证所有修改，反馈慢、成本高，也难以区分机制正确、UI 可用和研究有效。

## Solution

在当前 dsh、Hima、Electron 与 Pack 架构内按小切片打磨，提供三个递进的用户结果：

1. 可重复、低成本的本地开发与验证；一个有依据的默认研究样例。
2. 输入、启动、运行、阻塞、恢复、停止与报告全过程清楚可信，工程师能看到证据并采取下一步。
3. 接收 Step 4 的明确快照后，让 AI 在指定研究节点发挥算法与策略创造力，在预算内回溯/附加探索，交付 Pack 内知识资产，并帮助下一次研究。

主力回归使用 L1 真实纯函数和 L2 真实 Host/本地作业，L3 只证明必要的窗口行为。真实模型与真实工具分别做 L4 小验证，完整 DTCO 与使用价值集中在 L5。每一层都明确它能证明与不能证明的结论。

## Implementation Decisions

### 架构和事实权威

- 固定当前导入快照作为起点。Prototype 和旧 himaharness 只读；后续代码在 polishing 导入并验证。多包不拆成多领域上下文。
- 沿用 dsh Host/会话/工具体系，Hima 的 Pack、Fabric、Ledger、Judge、Job/Permit、Experience 与 Electron shell。优先 Pack 方法、现有函数和现有职责内的修改，不新增第二图引擎、模型驱动器、知识服务或预算服务。
- Ledger 记录真实执行；UI/报告是投影。模型提出假设、代码与探索，Executor 负责验证和记录，Judge 保持测量判断权威。
- 现有四类节点保持。参考图不可改写/删节点；附加研究属于执行轨迹，开始前验证影响范围和返回条件。跨多个模块的字段或契约变化必须列出全部消费者和兼容成本。
- 现有能力的验证任务先复现；若已满足要求，允许以验证证据关闭，不为任务量制造重构。产品缺口与确定性反例分别说明。

### 方法、研究与资产的语义

- 默认 local 方法改用已有 over-constraining chooser。目标可达、收敛未达标与预算截断分别验证；推断可达 period 不自动成为实际闭合结果。旧错误方法保留为测试反例。
- 输入预检只表达做过的静态检查；最终启动仍重新验证。当前 Goal 表单的固定字段只有在正式 Pack 的明确需求无法表达时才局部扩展。
- 附加探索的结构化提议带方法身份、输入/代码身份、影响节点、新节点依赖、输出/结束/返回条件。接纳前不产生研究 Job。重复提议幂等，非法或未支持的结构明确拒绝。
- 回溯保留历史，按依赖和内容身份决定复用；路径相同或 mtime 较新不足以证明有效。受影响下游重新执行，未完成结果不能被 Judge/Explore 当作新证据。
- 报告中的确定事实与模型假设分开。缺少观测、环境、算法或对照条件时说明限制；不由模型补造数值。完整交付必须有必要材料，而不只是一个终态标签。
- 运行资产的唯一位置定为已安装 Pack 内的 `run-assets/<runId>/`，方法 release 清单不包含可变资产。PLS-13 若发现上游已有等价且满足要求的位置，先记录唯一兼容映射并同步此规格，不能创建两套归档。
- 归档先写、核验、再声明完成；重复、中断和失败不破坏已完成材料。原 Site 报告保留，必要支持材料以内容身份纳入 Pack；不能因无 workspace 而丢弃本地已存在的早期失败事实。
- 历史资产仅作为有适用边界的研究输入。方法升级需要 owner/授权作者的明确确认；同客户升级保留资产，对外默认只发布方法文件，分享材料由客户选择。
- 预算范围仍以现有时间/尝试/代数/Site 资源为主。新增分支不能重置总体额度，模型收尾在总盒内部完成，硬界限后不继续研究调用。交付未完成状态可独立恢复，不为此新建运行服务。

### 任务划分与开工顺序

- 第一组 PLS-01～07：当前代码的测试、样例、输入/控制和报告；按每项依赖推进。
- PLS-08：Step 4 快照与能力交接。外部前置缺失时，不能把后续任务视为已可实施。
- 第二组 PLS-09～17：真实 AI 小研究、参考图保护/回溯、预算收尾、方法身份、归档、研究报告、再引用与 owner 升级/分享。
- PLS-18：所有必要能力齐备后进行真实 DTCO 与第二次引用。

任务标签 `ready-for-agent` 表示规格充分、无需重新 triage；不表示可以忽略 `Blocked by` 或外部资源前置条件。具体 DAG 和原 POL 对应关系在任务索引中。各任务都有独立结果与回滚要求，跨模块热点共享不构成并发修改许可。

## Testing Decisions

### 有效的测试与最低层级

测试针对用户/调用者可观察行为，通过生产使用的接口执行；纯函数的小输入使用独立期望，持久化/状态/权限使用真实 Host 和文件。只替代昂贵外部模型/EDA，不复制 Fabric/Ledger/Host 语义。不为纯文字或样式编写重复实现的断言。

| 层级 | 复用的接口 | 标准与触发 |
| --- | --- | --- |
| L0 | Node/version、seam、TS、Pack/schema、build | 相关修改必做；同轮构建一次，依赖 lib 的测试必须基于当前产物 |
| L1 | 已有公开纯函数/声明接口 | 算术、参数、图合法性、数据投影等边界组合；不能认证存储或窗口 |
| L2 | 真实 in-process dsh 或真实 HTTP Host、临时 Ledger/文件/local Job | 主力回归：状态、权限、重启、有效性、归档、错误和模型 replay |
| L3 | 现有 Electron driver、local Site | 仅真实窗口的启动/会话、传值/点击、刷新、取消/继续、可读性与入口；相关 UI 变化及 checkpoint 选择必要场景 |
| L4 模型 | 实际 DeepSeek V4 Flash + 有界任务 | prompt、知识、工具 schema/模型调用变化后做最小验证；记录真实产物，不能以固定回答判分 |
| L4 Site | 显式真实 SSH/报告/最小工具作业 | Site、wrapper、报告格式、Job/恢复/传输语义变化时；先只读核对和限定作业 |
| L5 | 实际模型、Site、正式 Pack 与资深工程师 | 研究闭环、材料交付和真实价值；只用于候选试点及实质影响研究行为的变更 |

### 强制验证反例

1. 本地测试加载即访问 SSH；空用例和缺 fixture 被算为通过。
2. 新安装没有声明文件；源码变化后测试旧 lib；同一轮重复 build。
3. 零 slack 下放宽策略被错误称为探索成功；未测的 next strategy 被当测量结果。
4. 过时 Pack 预检结果覆盖当前选择；无效输入创建 Run/Job。
5. cancel requested 被称为已经停止；恢复重复启动；旧状态覆盖终态。
6. 图提议删除参考节点、绕过必需 Judge、非法返回或无限增长。
7. 修改代码/输入后复用旧下游；未完成报告或别的分支同名文件被当当前证据。
8. 分支/重启重置总预算；收尾被算成预算外额外模型调用。
9. 半归档、坏 hash 或缺算法被称为交付完成；seed/升级删除已有资产。
10. 模型引用不存在记录、未知环境或其他客户材料；历史结论替代本次测量。
11. AI 候选自动变成默认方法；对外目录复制夹带客户研究材料。

每个反例在能够推翻它的最低层测试，并按真正受影响的外部边界补验证。比如坏图组合在 L1/L2，窗口只测一次合法附加分支的可见性与操作；文件升级矩阵在 L2，owner 确认交互才上 L3。

### 原有覆盖与成本记录

- 已有 prior art：`fabric-restart/retry`、`view-run`、`observe-ledger/readers`、`pack`、`ssh`、`strategy`、`budget`、`experience`、`window`、`honest-standin` 合同测试以及它们的 support。以实际断言逐项记录迁移位置，不仅统计文件数。
- 2026-09-11 基线历史证据：8 个本地文件 46 例通过约 15.8 秒；2 个选定 Electron 用例约 36.9 秒；另重复 boot 2 例。是 48 个不同用例，不是全量通过，也不是本轮新执行。
- 初始目标：日常相关 L0–L2 子集 3 分钟内，关键 L3 子集 5 分钟内；单次样本不是稳定 p95。记录首次安装/构建与重复执行，只有同覆盖对照才能宣称降本。
- 记录源 SHA、本地差异/产物身份、命令/退出码、pass/fail/skip/未跑、耗时、实际 Host/窗口次数、模型调用与 Site 作业投入。无法统计的字段写未测，不用测试数量推算。
- 不在同进程并行操作不同 in-process home 的全局环境；driver 串行；Site 遵守现有 Job/许可证额度。清理仅限测试自己的资源。
- 失败保留首次证据，转到最便宜的复现层定位；不反复完整 desktop 或真实 EDA 直到碰巧变绿。

## Out of Scope

- 迁回旧 himaharness 架构、重建 Host/Fabric/Ledger、另建图/模型/知识/预算服务。
- 全量 UI 重写、新通用表单框架、无限层级图嵌套或任意修改参考方法。
- 以最高层 desktop 承载每个数值/状态/文件组合，或以降低测试数量冒充降本。
- 依赖更强闭源模型替代指定基线；模型直接写 verdict 或改 Goal。
- marketplace、多租户权限平台、通用多 Site、多 OS 打包/商业签名和货币计费系统。
- 承诺固定 Fmax 提升、普遍 PPA 收益、一个固定硬截止日期或未授权的无限试验。
- 本次生成 spec 同时实施产品代码、触发真实模型/EDA 或改动源项目。
