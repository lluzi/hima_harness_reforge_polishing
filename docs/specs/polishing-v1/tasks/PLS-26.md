## 修改内容

1. 指定一位没有参与产品实现的工程师，在完成一次 Site 准备后，通过桌面和对话选择 Pack、提供输入、开始、介入并读取结果。
2. 开发者只观察并记录；不能代操作后称为独立复现。用户身份和数据按其授权留档，不要求公开个人信息。
3. 记录提问、卡点、错误提示、研究结论理解和知识资产可取得性；问题按最小可复现模块拆修，必要时重验受影响路径。

## 验收标准

- [ ] 被测 commit/Pack 版本/环境/预算明确；操作由实际受试工程师完成，有其结果确认。
- [ ] 无需日常编译源码或手改内部 YAML；准备阶段与日常使用分开记录。
- [ ] 工程师能区分执行成功、指标未达标、有效负结果与未验证内容，并能取得报告/算法及证据。
- [ ] 未安排真人或未完成使用时保持未验收，Agent/replay/开发者演示不可代签。

## 分级测试

- L3：复用已经通过的发布候选关键窗口记录。
- L5 使用验收：实际工程师完成；重用适用的真实研究资产，不为了访谈人为增加完整 EDA Campaign。若复现结论要求重跑，单列资源。

## 交付证据

记录实际 commit、构建/Pack/输入/环境身份、命令及退出码、通过/失败/跳过/未跑、耗时、Host/窗口启动数、模型调用与 Site 作业数、材料 hash 和原断言去向。每个本地提交立即推送并核对远端 SHA。

## 不在范围内

不改只读源项目，不新增第二图/模型/知识/测试服务，不将 stand-in、replay 或上游历史记录称为本版本真实研究通过。纯重构只有本切片的有效反例或交付要求需要时才做。

## 回滚

保留所有使用观察与候选版本；发现阻塞则回到上一可用版本并登记缺口，不删除失败验收。
