## 修改内容

1. 报告覆盖研究问题、假设/策略、算法或脚本、输入/环境、试验与比较条件、观察、取舍、局限和下一次建议。领域内容来自 Pack 与有来源的模型产物，事实由测量/记录支持。
2. 将环境“声明值”和本次“实际探测值”分别注明；无法取得的工具版本/设计身份保留未知。
3. 失败分析分别说明执行故障、证据不足和当前覆盖中的负结果；可能原因标为假设，并给出能够区分它们的下一次实验。
4. 聊天、工作台和最终归档能到达同一代码/报告/数据身份；报告叙述不能改写 Judge 的测量结论。

## 验收标准

- [ ] 任取一个报告结论可定位输入观测、脚本 hash 和适用环境；算法在归档中实际存在。
- [ ] 没有 Fmax 提升时不暗示提升，但仍可交付证据支持的限制和下一步；预算不足不写成搜索空间已穷尽。
- [ ] 模型给出不存在的记录 ID、凭空数字或与实际测量矛盾时，标明未验证/拒绝进入确定事实区。
- [ ] 旧版本报告仍可读，新增研究段落的不足不会被空模板掩盖。

## 分级测试

- L0：相关 source/schema 类型检查与一次构建，保证测试使用当前产物。
- L1/L2：使用明确真/假引用、对照条件差异、残缺输入验证报告与归档。
- L3：一次报告/代码下钻，检查关键段落的真实可读性。
- L4 模型：在真实小研究上审阅解释及下一实验的可执行性；不以固定文本匹配评判质量。
- L5：研究价值由资深工程师复核。

## 交付证据
