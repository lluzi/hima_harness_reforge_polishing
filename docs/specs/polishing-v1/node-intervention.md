## 必须达到的产品行为

Agent 与 Fabric 的关系是持续双向交互。工程师或获授权的 Agent 可以在运行中提出控制意图；Fabric 检查目标、状态、权限与影响，记录接纳/拒绝并执行；实际效果返回 Agent 和运行图。Fabric 保有执行与事实权威，Agent 保有研究、策略与代码工作的职责。

每个参考或附加节点、包括当前没有执行的节点，都能被定位和检查。所有节点类型均有明确的调度控制入口；操作适用性由节点性质和实际状态决定，并返回不可用原因。此要求不授权删除参考节点、直接伪造 Judge 判定或修改运行中的活动文件。

运行介入由 Fabric 提供为通用能力，不依赖 Pack 在相应位置预先插入 Human Handler、人工等待钩子或专门的 wait 节点。

必须支持这条具体路径：

1. 工程师在图中选择 B，或在对话里明确命名 B，并要求暂停、检查或修改。
2. Agent 获得可核对的节点引用，读取它的当前执行位置、输入/算法身份、输出、Job、预算和可用操作。
3. 控制请求定位到本次 Run、图/方法、节点以及相关代际、Loop/branch/attempt；Fabric 判定请求此刻是否适用。
4. Agent 和 UI 得到真实回执。仅“接纳暂停请求”不能显示为“现在可安全修改算法”；实际仍运行或无法确认的 Job 必须继续显示。
5. 暂停生效后，Agent 可以读证据、在该 Run 的隔离工作区准备算法修订并验证，声明影响范围；不得覆盖当前仍有读者/执行者使用的文件。
6. 接纳新算法版本后保留旧代码、旧尝试和旧输出，只复用仍有效的结果。需要重跑 B 及依赖它的下游时按 PLS-11 执行。
7. 继续需要符合用户授权或请求明确声明的继续条件；单纯完成一段代码编辑不自动撤销用户的暂停要求。

## 当前缺口

- `tools.ts` 当前只有 `hima_observe`、`hima_run`、`hima_resume`、`hima_cancel`。`hima_observe` 是读取报告形成观测，不是完整的节点控制/检查 API。
- 当前 `hima_run`/`hima_resume` 工具会等待整段驱动返回；不能假定左侧 Agent 在此期间已经能够处理新的控制意图。开始/继续需要及时返回可追踪身份，或使用 dsh 已有的后台工作机制，使对话控制路径在 Job 未结束时仍可工作。现有 `onOpened` 与 UI 开始接口可供复用；不另建模型驱动器。
- `fabric.ts` 提供开始、解除等待和图推进；`ledger.ts` 的 RunStatus 目前没有独立的人为暂停表示。现有 Hard blocker/wait 语义不能直接充当人为暂停，不能给正常介入伪造失败原因。
- `client/HimaWorkbench.tsx` 当前展示已记录节点顺序；节点尚无传给左侧 Agent 的选中引用。前端选择不等于模型已经知道“这个节点”是谁。
- PLS-09 覆盖 AI 算法研究，PLS-10 覆盖附加节点，PLS-11 覆盖修订后的有效性与重跑；它们没有完整规定运行途中从对话发起暂停和继续的共同控制入口。

## 控制接口草案

下表为语义，不冻结函数或模型工具的最终名称；实现前核对已交接源码。接口放在现有 Hima 操作层，由工具、命令和 UI 共用，不新建控制服务或第二图驱动器。

| 语义 | 请求的关键内容 | 必须返回的事实 |
| --- | --- | --- |
| 定位/检查节点 | Run、节点及执行位置；可查询尚未运行的参考节点 | 当前状态、实际 Job、输入/代码/输出身份、依赖关系、可用操作及限制 |
| 请求暂停 | 精确目标、前/后边界、影响范围、请求身份、预期读取版本 | 接纳/拒绝；何时及在哪里生效；仍运行或未知的工作 |
| 查询介入结果 | 原请求身份 | 当前阶段、已生效范围、关联记录及未完成原因 |
| 准备/接纳修订 | 暂停依据、旧/新代码与策略身份、验证证据、影响节点 | 接纳/拒绝、历史版本、必须重跑和可复用的结果 |
| 继续/重跑 | 已确认的暂停/修订身份、精确恢复位置 | 实际启动或复用哪些尝试、消耗何种预算；不存在悄悄重置额度 |
| 明确终止 | 用户要求立即终止的范围与实际 Job 身份 | 停止请求与实际观测分开，保留部分产物并标记其有效性 |

“这个节点”必须有可审阅引用：例如图上的选中节点加入当前对话的引用信息，或 Agent 先调用节点检查。不能只靠猜测一个全局 currentNode。选择变了、节点已前进到另一代、方法变化或原尝试已结束时，应拒绝过时请求或重新解析并说明；不得悄悄作用到新的尝试。

请求应具有可去重身份，带请求者/Agent 与目标上下文。状态变化与操作回执进入既有 Ledger；查询和自然语言说明从这些事实派生。图上的按钮与 Agent 工具不能拥有两套不同的暂停逻辑。断开模型会话不会自动撤销已经生效的暂停，重新打开窗口也不能丢失它。

算法修订的约束不能只写在提示词中。通过普通 Coding 工具直接改了同名文件，不等于已经接纳新的执行版本；既有工作区、内容身份和有效性检查必须识别这种变化，避免活动 Job 读到混杂版本、后续节点静默复用旧结果。普通代码工作与已接纳的 Run 执行材料之间的写入范围，交由现有工作区/工具边界落实并与 PLS-11 对账。

## 待确定的暂停默认语义

已向用户提出以下建议，尚未收到选择时保持为提案：

- 默认在安全边界停止后续推进，允许当前不可抢占的 EDA 作业完成并保存输出。
- 用户明确要求立即停止时，通过已有 Job 控制终止，保留日志和残缺产物；未完成产物不能用作有效结论。

不得把 OS 进程冻结（例如 SIGSTOP）当成通用的、低成本的可恢复暂停：它不自动释放许可证，也不保证工具检查点/外部副作用可恢复。工具若明确支持检查点，使用其声明能力并如实说明恢复成本。

“暂停 B 之前”若已错过该边界，不能谎报成功；必须明确当前位置和可选的后续边界。暂停不能重置时间/尝试/并发额度；人工等待怎样计入已有 Budget，须在开工的状态设计中明确并测试。

并行时，首先识别 B 及受其变化影响的下游。无关分支不应被默认为取消对象；若共享代码或资源导致无法安全局部暂停，应说明需要扩大范围，不擅自修改仍被其他分支使用的材料。

## 实施落点与安排

| 模块 | 需要改进的职责 |
| --- | --- |
| `tools.ts`、`commands.ts`、`remote.ts`、`index.ts` | 共同的节点查询与介入操作入口；Agent 与用户身份/目标/回执；复用既有注册与会话围栏 |
| `fabric.ts`、`node-turns.ts`、`forks.ts`、`job-cap.ts` | 在节点/Job 接纳边界尊重已生效控制；精确作用域；不再启动受控范围内的新工作 |
| `ledger.ts`、`runs.ts`、`recovery.ts`、`budget.ts` | 介入请求/效果的真实记录、并发去重、重启保留、预算及新旧记录兼容 |
| `jobs.ts`、`channel.ts` | 查询/终止实际 Job；区分调度暂停和工具进程状态，不引入假挂起语义 |
| `workspace.ts`、`generations.ts` | 接入 PLS-11 的代码修订、历史、有效性和受影响下游 |
| `client/index.ts`、`client/HimaWorkbench.tsx`、`client/HimaRunCard.tsx`、`client/api.ts`、`card-labels.ts` | 节点可选择/引用、Agent 获得明确上下文、控制请求与真实效果同屏显示 |

以上为消费者清单，不要求每个文件都修改。实现前列出真正新增的记录/字段及其消费者，并比较最小方案。新状态需明确旧版本拒绝或迁移行为，不能让旧代码忽略暂停后继续运行。

安排分三段：

1. **节点控制基础切片**：定位/检查、暂停请求及回执、继续、并发/重启。可先以确定性工具调用和 local Jobs 验证，不必等待真实算法研究成功。
2. **研究修订衔接**：PLS-09/11 使用同一入口完成分析、算法版本更新与受影响下游重跑，不另建修改路径。
3. **对话与 pilot**：模型工具 schema/prompt 接入后，用 DeepSeek V4 Flash 验证自然语言意图到正确节点控制；PLS-18 验证真实业务价值。

运行时实现开工前必须与 prototype 对齐固定快照/重叠修改归属；基础控制是否采用独立的小快照衔接，由实际差异决定，不把“等待全部 AI 研究成熟”当作忽略该基础能力的理由。本文件不授权把原型进行中的工作树拼进 polishing。

## 分级验收

- **L0/L1**：节点寻址/状态适用性、作用域和受影响依赖、过时请求、记录兼容；期望从独立反例得出。
- **L2 主力**：真实 Host、Ledger、本地文件和 Job。覆盖 B 前/后暂停、请求和 Job 启动竞态、重复 Agent/UI 请求、A→B→C 与无关 D、fork/join、修订失败、暂停中预算耗尽、Site 不可确认，以及在请求接纳/生效/修订/继续各处中断重启。
- **持续可介入性**：在长 Job 尚未结束时，Agent 开始调用已返回追踪身份，新的检查/暂停调用可以生效。模型研究节点使用的长会话也不能独占工程师发出介入要求的通道；L3 的草稿保留不能代替这条 L2/L4 验证。
- **L3 小集合**：图中选 B → 对话引用 B → 暂停回执 → 检查输出 → 修订/继续；验证图与对话看到同一节点尝试和同一效果，不把所有竞态搬到窗口。
- **L4 模型**：真实 DeepSeek V4 Flash 的节点识别与工具使用，验证未收到生效回执不会宣称已暂停/已修订。真实 EDA 终止或检查点语义变化另做小 Site 验证。
- **L5**：在复杂 DTCO pilot 中由工程师介入一次，改变后续研究，同时保持完整证据和结果有效性。

本次只核查和补充要求/规格，没有执行上述产品测试，没有宣称节点介入已经可用。
