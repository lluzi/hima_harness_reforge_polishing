# 由对话 Agent 主导业务节点执行

用户于 2026-09-11 明确决定：Hima Harness 中与工程师交互的同一个 AI Agent 是业务执行主体。它依据 Pack 的参考路线和当前运行事实，执行节点内的研究、代码及工具工作，判断结果并决定下一项业务动作。Fabric 为它提供运行上下文、合法动作、依赖/权限/预算约束、作业追踪、验收和恢复依据。

该决定替代上一版 PLS-19 中“Fabric 自主跑图，Agent 从外部介入”的主路径设想。执行机制和事实权威仍属于工具实现及 Fabric/Ledger/Judge；业务推进权属于对话 Agent。把整个旧 `drive` 包成一个 Agent 工具、只在少数节点插入 AI 调用，均不满足这个决定。

继续遵守 ADR-0001 的现有模块优先和 ADR-0003 的参考图保护。此次是执行职责的实质调整，会影响入口、调度、恢复、记录与测试；不能把“不新增服务”表述成没有架构影响。优先拆解和复用已有 Fabric/节点/Job 操作，使用已有 dsh Agent 循环，不引入第二执行主脑或第二图引擎。

## 后果

- 一个 Run 的业务推进只能有一个明确所有者；旧 Fabric 自动推进与 Agent 推进不能同时作用于它。
- Agent 无法继续时，已启动 Job 的运行、观测和硬约束仍由基础设施管理；新的业务节点等待 Agent 恢复，不由 Fabric 自动接管决策。
- Agent 可以请求节点完成，但不能通过自述直接写入成功。输出、内容身份、判定及必需条件由实际检查确认。
- 人类通过同一个对话 Agent 修正执行；长作业等待不能使该控制通道失效。直接停止与预算强制终止仍由基础设施可靠执行。

接受的是执行主导权与职责方向。具体节点操作协议、Agent/Run 绑定、在途 Run 迁移和暂停策略仍需设计与验证；此 ADR 不声明现有代码已经切换到新模式。
