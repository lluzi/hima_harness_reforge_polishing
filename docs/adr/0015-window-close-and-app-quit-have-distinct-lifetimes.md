# 关闭窗口与退出 App 具有不同生命周期

用户于 2026-09-23 在需求澄清 R2/Q11 中确认：第一阶段关闭窗口应保留已授权任务的后台运行；明确退出 App 后不承诺 Agent 在服务器继续整条研究流程，重开时核对实际状态并在原授权、预算和控制允许时接续。这样将日常让出界面与彻底结束本地程序分开，而不默认引入独立服务器 Agent 服务。

R3/Q13 确认：明确退出时，默认等待当前步骤达到可恢复边界再退出，不再启动新步骤；等待仍受原预算约束。用户要求立即退出时，明确选择停止或保留在途作业，产品说明实际状态与无法保证的部分。退出本身不等于取消整个 Campaign，也不能把“停止请求已发出”显示为 Job 已停止。

这是目标行为，当前实现仍会在关窗口时退出 Host，尚未修改。远端已启动 Job 可能独立存活，不能被显示为 Agent 仍自主推进。人类暂停、未知副作用及预算用尽继续阻止自动接续。等待退出可能耗时较长，因此保留明确的立即退出处置；具体 checkpoint 与进程/预算约束在 A3/F2 验收中验证。
