# HimaTeam 复用已选运行时、聊天与记忆组件

## 后续范围修订（2026-10-09）

用户明确取消首期群聊/IM。本文的 Zulip 必选、完整聊天 UI、Bot/频道及其分发与备份要求由
[ADR-0024](0024-himateam-collaboration-without-im.md)取代；其余运行时、记忆、单一 DBOS 权威
与双平台要求继续成立。下文保留原决定的历史原因，不作为继续实现聊天栈的依据。

2026-10-09，用户明确选择在 OAR、Pi、OpenCode、Zulip、DeepSeek Harness 和 Hindsight 上建设
HimaTeam。升级 DSH 继续承载 Hima 产品；OAR 接入 Pi/OpenCode；Zulip 承载可见团队对话；
Hindsight 承载可检索记忆与知识。现有 DBOS 的持久执行与恢复权威不变，Hima 保留成员身份、
团队契约、权限、成果验收与经验采纳责任。选择这些组件是为了复用已有能力、限制自研范围；
后续发现其他项目不自动重开整套选型。

这一决定接受 Zulip 与 Hindsight 服务作为先前“不预设新增聊天或知识服务”的明确例外。
不再同时引入其他完整 Agent 平台、聊天服务器或记忆引擎。团队业务分工由成员及其契约决定，
聊天投递、运行时状态和业务交付分别记录；Zulip 消息不是 DBOS 成功凭据，Hindsight 检索结果
不是已采纳规则的权威。

代价是承担组件间身份与数据关联、兼容版本、服务部署、真实停止/恢复与权限边界的集成。
具体版本、UI 嵌入方式和开发工期仍须论证验证。本决定记录组件与责任选择，不表示已安装、
已接通或已通过首期验收。详细论证见[固定技术栈架构](../research/2026-10-09-himateam-fixed-stack-architecture.md)。

后续用户明确确认 OpenCode 与 Pi 都属于 Resident Agent，可被 Fabric 任务直接使用，也可
承担 HimaTeam 成员工作。这一确认限定复用同类运行时接入，不将它们按使用场景拆成两套实现；
成员的长期身份、角色与执行会话分别表达。三者更细的分工建议见产品定义中的边界澄清。

Q26 进一步明确首期交付约束：Hima Harness 安装包须配齐上述组件及其运行依赖，包括
OpenCode 与 Pi；macOS 和 Linux 都可本机运行完整团队环境。此前“Linux 服务先部署、
Mac 仅作客户端、完整 Mac 打包后置”的建议未被接受。集成安装与依赖生命周期属于首期
工作，不能转嫁给用户手动部署。Q34 随后接受 macOS 包内受管 Linux 虚拟运行环境方向，
具体 VM/容器引擎、服务布局尚未决定，也未取得平台验收证据；组件选型和单一执行权威保持不变。

此取舍来自 Zulip 官方生产服务端的 Linux/Docker 部署要求与双平台完整入包要求之间的
兼容边界：由 Hima 携带并管理运行环境，可避免用户另装 Docker 或准备服务器，也避免
为 macOS 自行维护 Zulip 原生服务端移植。代价是包体、内存、磁盘及升级维护开销，尚无
实测总量。Hima 负责其启动、退出和数据生命周期，不将其扩展为退出后持续工作的平台。
具体技术选定前需验证安装、运行、停止、升级与数据保留；方向获准不等于验证通过。

Q27 确认负责人角色可使用 Pi/OpenCode，DSH 不作为每个团队必需的额外业务负责人；现有
DSH 会话绑定的 owner admission 需要适配。Q28 将运行生命周期限定在 Hima Harness
运行期间：退出即终止本次团队执行，不为退出后持续工作引入常驻执行服务。任务记录与
成果保留，外部效果及资源停止仍以实际核对为准；后续恢复不等于退出后后台运行。
