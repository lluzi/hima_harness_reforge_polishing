# HimaTeam 首期保留可靠协作，取消群聊与 IM 依赖

2026-10-09，用户明确将团队协作与聊天呈现分开：首期仍需独立角色、长期成员身份、
Pi/OpenCode 混编、成员间通信、Fabric 委派和共同达成目标；取消群聊及接近即时通讯工具的
体验。用户允许在既有架构内开发简单消息机制，以任务与成员工作视图、定向追加要求、附件、
实际输入输出及工具记录承载交互。本决定取代 ADR-0023 的 Zulip 必选与聊天配套要求。

HimaTeam 定义组织、职责和协作契约；成员及负责人承担业务判断。Fabric 约束和接纳可独立
委派的工作，DBOS 仍是机械推进与恢复内核；OAR 接入 Pi/OpenCode 的会话输入、输出和控制。
成员可在获授权任务内请求委派或调用 Fabric 能力，不因此成为其他任务的 owner，也不将每次
工具调用或信息交换展开为工作流节点。固定编排与成员自主分工使用同一执行权威。

首期在现有 Host/Cordis 中实现窄职责的协作消息服务，复用现有数据库与控制接口，不引入独立
聊天服务器、消息代理或新调度器。消息保存真实发送者、任务、收件成员、正文及材料引用；先
持久接收，再按成员与任务的授权、忙闲和停止意图投递。运行时接收与业务处理完成分别表达。
派工、提问、交接、复核和纠正可触发相关成员；普通进度、回显和自身通知不引发自动回复循环。
人的暂停、停止和撤权走既有控制入口，不排在普通消息后等待模型理解。

用户从任务工作台查看成员分工和依赖，进入成员详情查看实际收到的输入、输出、可观测工具
调用与产物，选择负责人或具体成员补充要求、上传材料和处理人工决策。首期不建设频道、群聊
线程、@ 解析、在线状态、已读回执或聊天搜索；输入框不要求复刻 IM。成员通信无需用户转述，
协作记录可见不等于将所有材料灌入每位成员，也不要求暴露内部推理或未观测的子 Agent 活动。

## 影响与保留边界

- 移除 Zulip 服务、Bot 同步、专用 WebContentsView、聊天室配置及相应安装/备份/恢复项。
  Ant Design X、QM、Koishi/Satori 均不因本次决定成为新依赖；相关研究仅供后续有界复用评估。
- 团队定义和成员经验、Hindsight、两类业务验收、附件、独立任务来源、人工节点与退出后受控
  继续均保留。取消群聊不把 Team 降级为一次性 subagent 或仅有负责人摘要的后台执行。
- macOS/Linux 首期完整安装要求不变。受管 Linux 环境仅按 Hindsight/执行隔离的实际需求
  独立验证；不再为聊天默认引入，也不能凭取消 Zulip 就宣称整个产品不需要 VM/容器。
- 代价是由 Hima 维护最小消息持久化、定向投递、状态核对及工作视图；收益是移除完整 IM 的
  身份同步、服务运维和前端嵌入成本。尚无运行验证或人日测量，不能据此宣称实现很小。
- 当前修订对象是本地产品定义、规格、计划和未发布 ticket 草稿。GitHub #97 仍为旧快照，
  发布前须同步；旧计划评审不能作为新消息方案的通过凭据。

## 评审收口澄清（2026-10-10）

用户接受评审后的收口建议。首个成员激活（包括纯讨论）进入既有受控 Run/effect；只有未激活
成员的草稿可无 Run。独立执行沿用有效绝对期限、资源和停止门，不让可选预算成为无限执行。
人类答复沿用本实例的已认证操作者身份并跨交互会话绑定，不新建多人目录或可派工人类 roster。
GitHub 写操作边界须由实际权限与正反用例证实，凭据名称或角色提示不构成证明；具体受限接法
由现有模块内资格验证决定，不预设新合并发布平台。中文记忆验收为固定模型组合的必要用例。
规格、计划及工单草稿据此同步，旧文档中 #97 待同步的表述属于此前阶段，不是继续派工依据。
