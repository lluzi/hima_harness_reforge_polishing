# 在当前 prototype 架构内持续打磨

用户明确决定：polishing 以 `hima_harness_reforge_claude` 当前架构为基础，非万不得已绝不新增组件。`himaharness` 的底层架构不同，其架构仅供参考；旧版能力对标不能成为迁回旧架构或重建组件的理由。

用户在访谈 Q5 中明确：“新增组件”的关键代价是使很多现有模块必须适配，引入新的边界测试，并长期增加代码治理负担。已有组件能运行 Pack、但质量不够好时，优先在现有职责划分下改进函数、逻辑和行为；只有极大的收益才可能支持组件例外。例外的具体收益与适配成本须在实际出现必要性时论证，不能从功能愿望直接推出新增组件。

本文编号属于 polishing 工作区，prototype 原有 ADR 保留各自的来源身份。

## HimaTeam 产品扩展中的澄清（2026-10-09）

在用户明确新增 HimaTeam 平台能力后，用户进一步确认：不必绝对禁止新增实体；当新实体或组件
带来明显收益时可以增加。对 HimaTeam 的设计，判断依据是具体消费者、现有职责无法合理承载的
缺口、减少的耦合或重复工作，以及新增的实现、迁移和维护成本，而不是机械限制实体或依赖数量。
领域身份、普通代码模块、运行进程、第三方库和独立服务分别论证。原有单一执行权威与独立验证
约束继续成立；本澄清不预先批准任何尚无必要性证据的服务或组件。
