1. Judgment: First make business results explicit, then choose the executor. Mechanism: frameworks can persist technical return values, not infer Campaign Goal or artifact truth. Case: current endRun requires Explore decision; Prefect completed flow may contain failed child state. Rival: a complete graph engine may replace legacy coupling. 2. Judgment: DBOS is first durability comparison if Postgres is acceptable; LangGraph is first graph-expression comparison. Mechanism: DBOS minimizes Node process restructuring but keeps code workflow; LangGraph supplies graph mechanics but creates checkpoint/upgrade obligations. Case: DBOS funcID result replay vs LangGraph Command+barrier. Rival: Temporal service may cost less over years than maintaining integration; Restate single binary lowers ops. Boundary: no measurement of net code or operating cost. Decision: choose one counterfactual engine, not stack libraries.

3. Judgment: Unknown external effect remains an honest state. Mechanism: external EDA effect and framework journal are separate commits. Case: DBOS zombie execution and Restate documented DB success-before-journal duplicate; XState restarts invocation. Rival: idempotent target and durable Job query can resolve most cases. Boundary: actual adapter protocol may close the gap, framework alone does not. Decision: effect ID/reconcile is retained beneath simplified node interface.

4. Judgment: Best foundation may be selected mechanisms rather than full adoption. Mechanism: core licensing, deployment, upgrade and domain migration costs can exceed saved scheduler code. Case: Effect unstable4.0 APIs, Restate BSL, LangGraph latest-graph resume. Rival: retaining own engine leaves durable correctness maintenance forever. Boundary: if A/B/C+upgrade comparison shows meaningful deletion and simpler operation, full engine wins. Decision: measurable stop/continue signals and no preselected architecture.
